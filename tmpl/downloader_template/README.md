# Smart module installer

MagicNet Installer 1.1.0 is still `magicnet_installer.zip`, not the core package.
For MagicNet targets it uses the same `installer/components` implementation as
scheduled module updates. The template's `smart/` source is generated by
`scripts/prepare-smart-installer.sh`; do not maintain a second updater there.

It reads stable release metadata over trusted GitHub TLS, authenticates the
component manifest against GitHub's asset digest, checks actual local bytes,
and compares core + missing components against the full package. Verified
cache hits and identical installed components do not cause payload/probe requests.
A repeated installation of the current intact version skips target installation.
Missing components are prepared in `/data/adb/magicnet-components` before the
manager is called. The module bootstrap independently verifies them again.

The template's existing isolated `install_module` delegation and failure
propagation are retained. The generic downloader remains for non-MagicNet targets.
No public mirror supplies trusted metadata. The smart path requires a componentized
stable module release (v1.4.8 or later), and fails explicitly on incompatible metadata.

Each normal module Release now also builds, checks, signs and includes the actual
`magicnet_installer.zip` from the same source, alongside core and full packages.
The reusable Kam template and separate installer channel remain available.

Build the reusable template with `bash scripts/prepare-smart-installer.sh` before
`kam build tmpl/downloader_template`. The host requires Go; Android does not need
Go, Python, jq or curl for the smart installer.
