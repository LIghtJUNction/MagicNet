# 智能安装与组件定时更新

`magicnet_installer.zip` 仍然是独立安装器，不是核心包的新名字。安装器 1.1.0 和模块内更新器共用 `installer/components` 源码、`components.json` 格式及 `/data/adb/magicnet-components` 内容寻址缓存。主模块 Release 构建会同时生成并验证、签名安装器，不再只交付 core/full。

安装器通过 GitHub HTTPS 取得正式版资产摘要，以 SHA-256 验证清单，然后逐组件检查当前文件、已暂存更新和缓存。对“核心包 + 缺失组件”与完整包的待下载字节数进行比较，选择更小的方案。相同版本、完整组件已安装或全部已暂存时，跳过载荷下载、测速和重复安装。核心安装需要的变化组件先进入共享缓存，再调用原管理器的 `install_module`；组件引导器再次验证这些文件。安装器不是永久后台服务。

元数据检查支持 ETag / 304，清单按可信哈希缓存。UI 的下载量是预计载荷字节数，不包含少量 HTTPS 元数据和测速开销。首次安装仍必须取得完整运行组件，不使用差分二进制补丁。版本兼容单位仍是一个完整 MagicNet Release；下载精度是组件，不把不同发行版的内核、脚本和 UI 随意混装。

在 WebUI 的“面板配置 → 智能更新”中设置开关、1–168 小时检查间隔、仅 Wi-Fi 和自动安装。默认关闭；启用后的默认计划是每 24 小时检查、仅 Wi-Fi、自动下载并暂存。关闭自动安装后仅检查。状态页包含每个组件的复用来源、下载量、检查时间、下次计划及错误；手动任务沿用现有后台任务和“输出”页进度。

更新器以模块管理器命令暂存完整兼容版本，并依赖现有引导器复用未变化组件。**不后台重启代理、不强制重启手机**；暂存完成显示“重启后生效”。设置和状态位于 `/data/adb/magicnet-update`，不依赖 WebUI 保持打开，也不会因更新模块文件被清空。禁用模块或移除模块后调度进程退出；关闭定时开关不撤销已经在执行的安装。检查失败从 1 小时指数退避到设置间隔，任务开始前无法确认 Wi-Fi 时延后。Wi-Fi 选项是启动条件，不是强制绑定接口；下载途中系统切到蜂窝网络的情况尚需真机验证。没有硬性墙钟准点保证，设备休眠/关机时延后执行。

```
cli update status
cli update check
cli update apply
cli update configure --enabled=true --interval-hours=24 --wifi-only=true --auto-install=true
```

只使用已知绝对路径调用管理器，拒绝无可信摘要、草稿/预发布、其他产品标签、清单与包不一致以及降级。不把网络或管理器失败显示成更新成功；自动更新和手动更新使用同一操作锁，原组件安装继续使用独立安装锁。所有载荷准备好以前不调用管理器。普通 I/O 回滚边界沿用组件引导器；不声称断电/SIGKILL 下整个系统更新事务可自动恢复。

验证包含 Go race、ETag/缓存/下载预算/坏载荷/旧版和待重启复用、真实组件引导器离线接力、安装器 ZIP/ELF/管理器隔离、WebUI 状态解析与后台任务回归。主机和 CI 不替代 Android 真机刷入、各管理器暂存路径及 ROM Wi-Fi 命令兼容性测试。
