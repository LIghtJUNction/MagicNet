# 核心包、组件包与完整包

发布流程同时生成以下产物，均在最终打包后生成校验和：

| 文件 | 用法 |
| --- | --- |
| `MagicNet-core.zip` | 刷入的小型核心包；安装时检查组件，按需补齐。 |
| `MagicNet.zip` | 核心包的兼容名称，供现有 update.json 与 installer 使用。 |
| `MagicNet-component-<id>-<sha256>.zip` | 独立组件载荷，由核心包自动安装；不是独立的 Magisk/KernelSU 模块，不要单独刷入。 |
| `MagicNet-full.zip` | 包含同一套核心与全部组件，安装组件不需要联网。 |
| `components.json` | 本次发行的组件清单：架构、精确文件路径、权限、大小与 SHA-256。 |
| `package-sizes.json`、`SHA256SUMS` | 实际包大小及最终发布文件校验和。 |

核心包保留安装脚本、框架、基础配置、组件更新器。`bin/` 中的 sing-box、CLI、ecapture、jq/yq、proxylink 等程序分别打包；MCP 使用同一个 CLI 程序，WebUI、Zashboard、规则集各自打包。删除构建时重复保留的 `.local/state/*.asset` / `*.archive`，不把下载缓存再塞进完整包。

## 安装与升级

组件清单来自正在刷入的可信模块 ZIP，而不是代理镜像提供的清单。每次安装逐项校验实际文件，顺序为：本次安装目录 → 上一版本目录 → 完整包内置载荷 → 显式指定的离线归档来源 → 网络下载。即便旧版本没有组件清单，只要文件内容相同，也能复用。默认不创建持久 ZIP 缓存。

组件 ID 由规范化后的 ZIP 内容计算，时间戳、文件顺序、MagicNet 的版本号不会让未变化的组件变成“新版本”。只改 WebUI 不会强迫下载同内容的 sing-box。文件缺失或校验不符时才更新。首次安装核心包仍要补齐全部必需组件；主要节省的是后续升级流量，不是声称第一次安装凭空减少全部运行文件。

下载地址固定到核心包所属的 Release 标签。不会把不同发行版的“最新”组件随意混装。GitHub 直连足够快时不额外测速镜像；否则显示镜像测速、选择可用路径，并显示下载进度。TLS 校验和嵌入清单中的 SHA-256 校验必须同时通过。Android 的纯 Go 更新器与现有 downloader 一样，使用公共 DNS 引导解析，不依赖尚未安装的代理内核；完整包及全组件复用路径不会发起下载请求。

所有组件先在模块内部的私有 `.components-install/` 目录暂存并校验，全部就绪后才写入目标目录。普通写入错误会回滚已替换文件；进程中断后，下次安装先恢复未完成的组件替换。下载失败不会先删除旧组件。只清理由上一份成功安装清单记录的过时组件文件及其空目录，不改用户订阅和配置。组件检查发生在现有配置迁移、权限与订阅引导逻辑之前。

下载文件放在本次安装的 `.components-install/.downloads/`，解压校验后删除。成功、普通失败和下次重试均有明确的清理路径，不再向 `/data/adb/magicnet-components/` 写入文件。升级复用实际安装文件，不需要额外保留各版本 ZIP。手工准备的离线归档可通过 `--cache-dir` 指定；它只作为读取来源，更新器不会写入或清空这个目录。

配置安装使用组件引导程序已经校验的规则文件，核心 ZIP 无须重复携带规则或校验工具。首次安装和升级共用模板准备与校验逻辑；原始未拆分 KAM 包仍可从 ZIP 取得规则。实际配置生效前必须通过 `jq` 和 `sing-box check`。

历史缓存、旧安装日志和可识别的临时备份通过[一次升级边界上的迁移](install-storage.md)清理。该迁移有明确的移除条件，不会变成开机扫描任务。

这些组件是同一模块的分发单元，不是改变网络策略或裁剪功能的开关。仍保持现有功能集与 TUN/eBPF 模式约束。

## 发布门槛

构建流程保留原来的单任务、精确提交构建方式，解决手动升版生成 `[skip ci]` 提交后无法等待独立质量工作流的问题。在 `Create GitHub release` 前，必须执行 `scripts/quality-gate.sh all`；独立 Code Quality 工作流也调用这个脚本的相应检查组：Rust 格式/Clippy/测试、Shell 与主机回归、组件测试、WebUI 检查和浏览器交互测试。

发布步骤同时要求质量门槛步骤的 `outcome == success`，校验构建与检查的子模块快照一致，再验证最终产物校验和。先创建草稿并上传全部文件，全部成功才公开 Release。检查失败、跳过、取消，或上传失败，不能公开新版本。

拆包会改变原 ZIP 的字节。`scripts/checksum-release-assets.sh` 在拆包之后生成并验证全部最终产物的 `SHA256SUMS`，包括核心、组件、完整包、清单和尺寸报告。构建和发布不需要 KernelSU 开发者私钥。

## 验证与边界

```sh
bash scripts/quality-gate.sh components
```

包含 Go 更新器测试（含 race 检查）、Python 真实 ZIP 打包测试、原生宿主更新器的离线安装与 Shell 引导测试、校验和及篡改检测，以及发布门槛失败测试。构建工作流继续运行原始完整模块的安装测试，并检查拆分后完整包的内容。

主机模拟测试和 arm64 交叉编译不等于 Android 真机测试。测试覆盖下载进程被强杀，以及组件替换在各个文件移动点中断后的重试恢复。恢复失败时只保留一个固定工作目录，并报告路径，保留旧文件供恢复。此保证限于更新器仍能访问的模块目录；模块管理器删除安装目录、存储损坏和突然断电后的文件系统持久性仍需设备验收。最终大小以对应构建产生的 `package-sizes.json` 为准，不使用夹具包大小冒充正式产物大小。
