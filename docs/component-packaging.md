# 核心包、组件包与完整包

发布流程同时生成以下产物，均在最终打包后重新签名：

| 文件 | 用法 |
| --- | --- |
| `MagicNet-core.zip` | 刷入的小型核心包；安装时检查组件，按需补齐。 |
| `MagicNet.zip` | 核心包的兼容名称，供现有 update.json 与 installer 使用。 |
| `MagicNet-component-<id>-<sha256>.zip` | 独立组件载荷，由核心包自动安装；不是独立的 Magisk/KernelSU 模块，不要单独刷入。 |
| `MagicNet-full.zip` | 包含同一套核心与全部组件，安装组件不需要联网。 |
| `components.json` | 本次发行的组件清单：架构、精确文件路径、权限、大小与 SHA-256。 |
| `package-sizes.json`、`SHA256SUMS` | 实际包大小及最终发布文件校验和。 |

核心包保留安装脚本、框架、基础配置、组件更新器。`bin/` 中的 sing-box、CLI、MCP、ecapture、jq/yq、proxylink 等程序分别打包；WebUI、Zashboard、规则集各自打包。删除构建时重复保留的 `.local/state/*.asset` / `*.archive`，不把下载缓存再塞进完整包。

## 安装与升级

组件清单来自正在刷入的可信模块 ZIP，而不是代理镜像提供的清单。每次安装逐项校验实际文件，顺序为：本次安装目录 → 上一版本目录 → 完整包内置载荷 → 持久缓存 → 网络下载。即便旧版本没有组件清单，只要文件内容相同，也能复用。

组件 ID 由规范化后的 ZIP 内容计算，时间戳、文件顺序、MagicNet 的版本号不会让未变化的组件变成“新版本”。只改 WebUI 不会强迫下载同内容的 sing-box。文件缺失或校验不符时才更新。首次安装核心包仍要补齐全部必需组件；主要节省的是后续升级流量，不是声称第一次安装凭空减少全部运行文件。

下载地址固定到核心包所属的 Release 标签。不会把不同发行版的“最新”组件随意混装。GitHub 直连足够快时不额外测速镜像；否则显示镜像测速、选择可用路径，并显示下载进度。TLS 校验和嵌入清单中的 SHA-256 校验必须同时通过。Android 的纯 Go 更新器与现有 downloader 一样，使用公共 DNS 引导解析，不依赖尚未安装的代理内核；完整包及全组件复用路径不会发起下载请求。

所有组件先在私有目录暂存并校验，全部就绪后才写入目标目录。普通写入错误会回滚已替换文件；下载失败不会先删除旧组件。只清理由上一份成功安装清单记录的过时组件文件，不改用户订阅和配置。组件检查发生在现有配置迁移、权限与订阅引导逻辑之前，这些逻辑继续保留。

缓存保存在 `/data/adb/magicnet-components/`，文件名为 `<sha256>.zip`，跨模块升级保留。缓存也会重新校验；缓存只是优化，不是信任来源。当前不自动清理历史缓存，避免把离线回退所需组件删掉；在没有安装任务运行时可手动清除缓存中的 ZIP，已安装模块不受影响。组件清单记录的 SHA-256 可用于把已下载的独立组件 ZIP 按此名称预置到缓存。

这些组件是同一模块的分发单元，不是改变网络策略或裁剪功能的开关。仍保持现有功能集与 TUN/eBPF 模式约束。

## 发布门槛

构建流程保留原来的单任务、精确提交构建方式，解决手动升版生成 `[skip ci]` 提交后无法等待独立质量工作流的问题。在 `Create GitHub release` 前，必须执行 `scripts/quality-gate.sh all`；独立 Code Quality 工作流也调用这个脚本的相应检查组：Rust 格式/Clippy/测试、Shell 与主机回归、组件测试、WebUI 检查和浏览器交互测试。

发布步骤同时要求质量门槛步骤的 `outcome == success`，校验构建与检查的子模块快照一致，再验证最终产物签名与校验和。先创建草稿并上传全部文件，全部成功才公开 Release。检查失败、跳过、取消，或上传失败，不能公开新版本。

拆包会改变原 ZIP 的字节，旧签名不能沿用。`scripts/sign-release-assets.sh` 在拆包之后对全部最终产物重新签名并验证，包括核心、组件、完整包、清单、尺寸报告和校验和文件。

## 验证与边界

```sh
bash scripts/quality-gate.sh components
```

包含 Go 更新器测试（含 race 检查）、Python 真实 ZIP 打包测试、原生宿主更新器的离线安装与 Shell 引导测试、签名验证，以及发布门槛失败测试。构建工作流继续运行原始完整模块的安装测试，并检查拆分后完整包的内容。

主机模拟测试和 arm64 交叉编译不等于 Android 真机测试。断电或 SIGKILL 跨文件提交的自动恢复尚未实现，不能把普通 I/O 错误回滚说成任意崩溃下的原子安装；保留的恢复文件路径会在提交失败时输出。最终大小以对应构建产生的 `package-sizes.json` 为准，不使用夹具包大小冒充正式产物大小。
