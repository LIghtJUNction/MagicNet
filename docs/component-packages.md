# 核心包、组件与完整包

每次模块构建生成以下发布资产：

| 文件 | 用途 |
| --- | --- |
| `MagicNet-core.zip` | 推荐升级入口。安装脚本、框架、配置模板、CLI/MCP 与组件安装器；大组件按需获取。 |
| `MagicNet-component-<组件>-arm64-<内容标识>.zip` | 独立组件数据包，由核心包安装器自动处理，不是独立的 Magisk/KernelSU 模块。 |
| `MagicNet-full.zip` | 含全部组件，不需要联网获取组件，适合首次安装或网络受限设备。 |
| `MagicNet.zip` | 与完整包字节相同，保留旧更新源、下载器和已有链接的兼容性。 |
| `components-manifest.json` / `SHA256SUMS` | 发布锁定清单与校验值；发布资产同时提供分离签名。 |
| `update-core.json` | 核心包的管理器更新源；安装核心包后，后续管理器更新仍下载核心包。 |

组件包括 sing-box、jq、yq、proxylink、ecapture（以实际构建包含的二进制为准）、模块 WebUI、zashboard 与规则集。核心包首次安装仍需要取得该版本列出的全部组件，不会为了体积削减现有功能。完整包只保证组件安装不依赖网络；订阅填写、获取订阅和实际联网仍遵循原有逻辑。

## 安装与更新

安装器逐项校验当前版本的 SHA-256 和文件长度。顺序是：完整包内置文件、当前安装目录、上一版模块目录、已校验下载缓存、网络下载。旧版本没有组件状态文件也可以直接复用，不能仅凭版本标签跳过文件校验。

只修改脚本、配置或模块版本号，不会改变内容相同的组件标识；修改一个组件，只会补下载那个组件。损坏、缺失或与目标版本不一致的组件才需要补齐。依赖以核心包内置清单为准，不会把另一个最新版本的内核混装进旧模块。首次安装总流量仍取决于实际所需组件；主要节省来自后续升级复用和移除重复构建缓存。

下载先测直连，必要时并行测 GitHub 代理并显示速度及下载进度。测不出速度不等于无法下载，不支持 Range 的线路仍会尝试普通请求。代理只能提供与内置清单哈希一致的内容。TLS 校验不会关闭；静态 Android 安装器显式配置 DNS 与系统证书目录。

组件全部完成校验后才替换目标文件；失败路径回滚已经替换的组件文件，不覆盖订阅和用户配置。这里不宣称能抵御进程被强制杀死或设备突然断电的所有情况。下载缓存位于 `/data/adb/magicnet/components`，仅清理该目录内属于安装器的旧内容寻址 ZIP，不把缓存再次打入模块。

首次使用核心包可手动刷入 `MagicNet-core.zip`。旧版独立下载器继续使用完整包以兼容旧发行版；不会把不存在的核心资产作为下载目标。

## 发布门禁

独立 Code Quality 和模块发布门禁调用同一份 `scripts/quality-check.sh`，包括 Rust 格式/Clippy/测试、Shell/主机回归、WebUI/浏览器测试及组件安装回归。

发布门禁运行在实际构建的工作区，检查提交 SHA、子模块构建快照和资产校验值。这样也覆盖手动工作流先提交版本号再构建的情况，而不是错误地等待旧 SHA 的独立 CI。任何失败、取消或跳过都无法通过发布步骤的显式 `success` 条件。上传先生成草稿，全部资产上传成功后才公开；失败留下的草稿需维护者检查后清理再重试，不自动覆盖已有发行版。

打包在 KAM 8000 签名前执行。完整包、核心包、组件包、清单和核心更新元数据统一签名并校验。构建下载缓存 `.local/state/` 从所有发行包排除。

## 验证

```sh
bash scripts/quality-check.sh components
bash scripts/quality-check.sh all
# 完整构建后：保留实际 Android 组件，仅替换主机测试用安装器。
bash scripts/package-components-smoke.sh dist/MagicNet.zip
```

测试覆盖重复安装、跨版本复用、仅更新一个组件、损坏缓存/文件、离线完整安装、旧模块迁移、路径/符号链接拒绝、下载失败和替换失败回滚、Range 不支持、签名篡改及发布失败门禁。主机测试和 Android 交叉编译不是手机真机测试。每次真实构建会输出 `packages_bytes`，包体大小应以该次构建产物为准。
