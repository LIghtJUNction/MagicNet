# GitHub 组件下载线路

适用范围：`installer/components` 下载公开、固定版本的 Release 组件。不改变 sing-box 的订阅节点、Google/GitHub 应用分流或系统代理；也不信任镜像提供的清单。

## 候选与来源

内置候选由 3 个增加到 7 个：`gh-proxy.com`、`ghfast.top`、`ghproxy.net`、`gh.ddlc.top`、`gh.llkk.cc`、`gh.jasonzeng.dev`、`ghproxy.site`。加上 GitHub 直连，共 8 条候选路径，不代表 8 个独立运营商或都能在某地高速下载。

2026-09-17 查阅的运营方说明：
- https://gh-proxy.com/docs
- https://ghfast.top/
- https://ghproxy.net/
- https://gh.ddlc.top/
- https://gh.llkk.cc/
- https://gh.jasonzeng.dev/
- https://ghproxy.site/

这些来源说明代理的用途，不是用户所在网络的测速结果。新增地址仅作为待测候选；不从陌生网页自动抓取并信任镜像，不向镜像发送订阅地址或令牌。镜像会看到所请求的公开仓库/版本/组件名称。

## 选择与切换

每次需要重新选择线路时，GET 当前实际组件，最多读取 1 MiB，单条探测最多 5 秒。检查响应大小、Content-Range、原始编码和 ZIP 文件头，拒绝 HTML/错误页；小于等于 1 MiB 的完整样本还要核对嵌入清单中的 SHA-256。超时但已收到至少 4 KiB、带 ZIP 文件头的片段，记录实际字节/耗时，而不是当成完整成功或“最快”。大文件采样不是完整文件的真实性校验。

直连只有在完整收到 1 MiB 且达到 4 MiB/s 时才跳过镜像比较；不再用 64 KiB 的瞬时结果、256 KiB/s 的门槛屏蔽其他候选。镜像最多 4 个并行，结果日志由单个收集者输出，候选去重并有数量上限。默认完整探测最多 8 MiB 应用层正文（不含协议开销和网络缓冲）；失败重选可能追加探测。慢候选会增加等待，扩充池不是零成本。

测速连接超时或样本中断的线路记为“未知”，排在测得速度的线路后，仍可进入完整下载尝试；不会把测速超时当成校验通过，也不会因此直接拒绝安装。明确返回 HTML、错误 Range 或校验不符的样本不会获得速度排名。

已验证的线路仅在本次安装进程内复用，5 分钟过期。小组件的成功不能让后续大组件跳过重新测速。实际下载使用 8 秒速度窗口：存在替代候选时，持续低于 128 KiB/s 且剩余超过 256 KiB，终止本次尝试、清理未验证临时文件并换线路。窗口在读取正文时检查；完全不返回数据仍由原有 20 秒空闲超时处理，因此不承诺精确 8 秒就必然切换。

所有替代线路失败时，可对先前排序最优且仍有进度的慢线路重试一次，不启用软速度门槛；原有请求超时、空闲超时、HTTPS 校验、完整哈希及安装事务仍有效。该慢速兜底不写成可复用的快速线路。这里没有实现跨镜像分段续传，切换会重新下载该组件，不混拼来源。

## 验证边界

新增测试覆盖首 64 KiB 突发误选、小文件缓存影响大文件、缓存过期、候选去重/并发上限、错误 Range/HTML/压缩/截断响应、正文持续低速、所有替代失败后的慢速兜底、超时回收，以及采样之后被篡改的内容仍被完整哈希拒绝。原有离线安装、缓存、签名/归属边界和原子安装代码不变。

这些是本机模拟网络和逻辑回归，不是中国移动/联通/电信或受影响手机的速度实测。测速和切换发生在安装设备上；不承诺公益镜像的长期可用性或最低速度。本修复不覆盖已经签名发布的 v1.5.6 文件，须由后续版本正常构建交付。
