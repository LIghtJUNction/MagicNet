# 多连接场景：减少连接归属查询的内存分配

## 修改范围

内核提交 `a8a4eaa5af32add819566dd0ec88a03683a363bd` 在 Linux/Android
连接归属查询中复用 64 KiB Netlink 接收数组，覆盖精确查询和 dump 回退。
缓冲区在解析结束后归还，每次查询独占；分流规则、进程身份匹配、超时、MTU、DNS
和节点选择均不改变。该提交建立在语音诊断修复 `6634121` 之上。

预期收益集中在频繁建立连接、多个应用同时联网时的临时分配和垃圾回收开销。
没有测量手机上的吞吐、延迟、耗电或丢包，不能据此承诺实际下载速度提升。
缓冲池可由垃圾回收器清理，也可能暂时保留数组；它不保证降低空闲常驻内存。

## 局部基准

2026-09-11，Go 1.23.2，linux/amd64，五次运行取中位数。
测试调用生产查询函数，通过本地 Unix 数据报套接字返回构造的 Netlink 响应。
并发测试设为 GOMAXPROCS 的八倍；cpu=4 时为 32 个工作协程。

| 场景 | 修改前 ns/op | 修改后 ns/op | 修改前 B/op | 修改后 B/op |
| --- | ---: | ---: | ---: | ---: |
| 单协程，cpu=1 | 4302 | 1131 | 65584 | 48 |
| 单协程，cpu=4 | 11043 | 1159 | 65584 | 48 |
| 并发，cpu=1 | 4876 | 1157 | 65584 | 49 |
| 并发，cpu=4 | 14938 | 339.1 | 65586 | 52 |

四组测试的每次堆分配次数均由 2 降为 1。以上为查询函数及本地测试夹具的开销，
不包含真实 Netlink 查询耗时、代理隧道或互联网传输；不能把时间比例用作网速增幅。
本地环境无法下载完整 Go 依赖，因此只运行了源文件级测试夹具，外部错误格式化
和协议常量使用了兼容桩。真实回环 TCP/UDP 归属查询在原版和修改版中均返回
ErrNotFound，未将该环境探测计为通过；完整仓库测试以 CI 为准。

## 复核

新增测试包含 32 路并发，IPv4/IPv6 身份隔离、短错误响应、截断消息和垃圾回收。
源文件级测试在原版及修改版各运行三次，修改版 race 测试运行五次，均通过。
完整内核仓库可运行：

```sh
go test -race ./common/process
go test ./common/process -run '^$' -bench '^BenchmarkSocketDiagBuffer$' -benchmem -benchtime=250ms -count=5 -cpu=1,4
```

比较旧版本时，仅将新增的 `socket_diag_buffer_linux_test.go` 复制到旧工作树；
生产源文件保持原样。测试期间固定 Go 版本、CPU 数与宿主环境。
真机验收应固定节点、网络和配置，对比单连接及多连接的吞吐、连接建立延迟、CPU、
内存和丢包。合并代码或基准通过不等于已经完成真机验收。
