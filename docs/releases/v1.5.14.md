# MagicNet v1.5.14

## 应用联网策略恢复

修正 v1.5.13 只能诊断、不能解除已确认应用联网限制的缺口。针对 #329 的证据，本版新增通过系统策略接口执行的恢复路径，不再把 sing-box DNS 正常误当作应用系统 DNS 一定正常，也不使用删除内核限制后即宣告持久修复的做法。

实现不匹配具体设备型号，不写死应用 UID，不内置 Google 专用放行列表，不修改代理节点、订阅、DNS 或 TUN/eBPF 模式。当前按能力支持 AOSP 的已知后台计费网络拒绝策略，以及存在对应 API 的 Oplus 已知移动/Wi-Fi/全部联网拒绝策略。未知厂商接口和未知策略保持 unsupported/unknown，不能据此声称所有 OEM 均已适配。

新增显式确认的 root CLI 操作：

```sh
cd /data/adb/modules/MagicNet
./cli --json network-access inspect
./cli network-access repair '<审查后的 candidate>' --confirm
./cli network-access check '<同一 candidate>'
./cli network-access rollback '<同一 candidate>' --confirm
```

确认前必须检查该候选的完整 packages 集合；共享 UID 的所有应用都会受到同一次策略修改影响。不要批量清除所有限制。AOSP 后台数据限制也是用户设置，不能仅凭策略非零就认定它是 Play Store 故障原因。

恢复前保存原策略和完整身份，写入后回读验证，失败保留回滚记录。重复操作幂等；身份变化、新策略冲突和控制器重新施加限制都会明确报告，不循环覆盖用户防火墙设置。私有恢复日志不应上传到 issue。

## 升级后须知

安装本版本不会静默取消既有用户/OEM 限制，需要审查后执行上述确认操作。WebUI/MCP/机器接口的 network-access 状态和检查仍保持只读；本版不新增机器写操作。

`configured_verified=true` 仅代表策略接口回读一致，不代表已经验证 Play 首页、登录或下载。已加入 Java 桥接、Rust 状态机、日志安全、回滚和并发回归测试；主机模拟测试不能替代真机验收。

**#329 保持开放：新接口写入后的真机应用 DNS、Play 访问、多 OEM 兼容性及厂商控制器重新施加限制仍需验证。此版本不是已证实的全设备永久修复。**

完整操作、异常恢复和验证边界见 [应用联网策略恢复说明](../network-access-recovery.md)。
