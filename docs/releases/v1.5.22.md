# MagicNet v1.5.22

[下载增量安装器](https://github.com/LIghtJUNction/MagicNet/releases/download/v1.5.22/magicnet_installer.zip)，或从[发布页](https://github.com/LIghtJUNction/MagicNet/releases/tag/v1.5.22)下载离线完整包。

本版减少闲置测速和连接处理的临时分配，修复部分 TLS 订阅导入问题，增加持续联网验收，并整理路由回归入口和架构文档。

- **减少协议识别的重复错误处理。** `PeekStream` 将一轮失败探测器的错误统一汇总，避免每次探测后重复展开和去重已累计的错误树，减少这条路径的 CPU 与垃圾回收开销。首个探测器成功时不增加内存分配，保留原有协议判定、顺序、超时和重读语义。
- **减少应用归属查询的临时对象。** TCP/UDP 的内核查询请求改为局部数组，IPv4/IPv6 请求编码从 80 B、一次堆分配降至零堆分配；受控基准中的完整查询从两次降至一次。请求字节、UID/inode 匹配、UDP 端点顺序与重试语义保持。它减少垃圾回收负担；手机核心 RSS、整机内存占用和续航改善仍未做版本对照验证。
- **闲置测速组按需启动。** 生成的主代理、AI 和代理链自动测速组启用 `lazy_start`；未使用时不在启动和网络重置时自动批量探测，首次使用立即启动测速，仍可手动强制测速。核心选项默认关闭，保留自定义组的既有行为。受控五组、每组 27 个节点测试中，闲置组启动和网络重置的探测均从 135 次降至 0 次；这衡量省去的请求数量，不是续航百分比。活动组、暂停、恢复、空闲和关闭另有回归验证。
- **保留 TLS 导入语义。** 修复原生备用解析漏读带引号 SNI 字段的问题。完整转换器不可用或失败时，无法完整保留 TLS/传输选项的输入会被拒绝，保留当前配置。网站诊断将本地 CA 文件读取失败与对端证书验证失败分开报告，继续验证证书。
- **联网验收增加持续观察。** 新增普通 Android 应用身份的 HTTPS 持续测试，记录请求失败、超过延迟预算的请求、核心重启、就绪状态丢失、内存增长和文件描述符增长。测试失败或设备失联时保留已收集结果；观测缺失返回未完成，避免留下旧的通过结论。
- **稳定性测试覆盖异常过程。** 增加持续测试自身的回归，覆盖请求失败、核心进程换代、未知状态和资源增长。测试结果区分通过、失败与未完成，进程仍在运行不能代替持续联网通过。
- **分流组出口需要分别核对。** Google、YouTube 和 AI 服务有各自的分流组；已固定节点的服务组不会随主代理节点变化。遇到反复高延迟时，先检查实际服务出口，再显式让适合的服务组跟随主代理，或为 AI 服务选择符合该组约束的节点，并读回持久选择。现场选择调整属于设备诊断处理，不会在更新时覆盖其他用户的有效选择。
- **维护中的路由测试统一入口。** 删除已退休的内嵌域名/IP 列表测试分支与重复的微信入口。主机测试按选项执行一次结构检查或真实规则资产检查；发布包始终检查维护中的分类器与实际资产，失败时不回退到旧模板。
- **架构说明合并并校正。** 将重复的运行架构文档合并到 `ARCHITECTURE.md`，说明配置意图、规范运行状态与恢复记录的归属。继续显式支持 `tun|ebpf`，默认 `tun`，保留模式切换的验证和回滚边界。

性能验证采用 Linux amd64、Go 1.27.1、`GOMAXPROCS=4` 的五轮微基准：一轮八个不同探测器全部失败时，普通流的中位耗时从 7759 降至 1564 ns/op，分配次数从 124 降至 20 allocs/op；带缓存分片时从 8966 降至 2792 ns/op，分配次数从 164 降至 60 allocs/op。相关协议、进程、DNS、传输和分组代码的 race 与 vet 检查通过。这些数字衡量局部代码开销，不能作为手机端到端延迟改善或节点千毫秒延迟已修复的证据。

在连接的 Android ARM64 手机上，用独立测试二进制、`GOMAXPROCS=2`、每项 100ms 的三轮对照复核：普通流八次拒绝的中位耗时从 20257 降至 4173 ns/op，分配仍为 124 降至 20 次；缓存分片为 30897 降至 3598 ns/op、164 降至 60 次。首次探测成功的分配保持不变。测试未替换运行核心，前后核心 PID 不变；短时间耗时会受 CPU 调频与调度影响，不代表新完整包已完成真机稳定性验收。

持续联网测试提供指定设备、目标和观察窗口内的证据。旧安装在早期 90 次请求、10 分钟窗口内通过，之后发生复发；恢复节点后的另一窗口 90 次请求无失败，但 27 次超过一秒、最高 5.5 秒，结论为失败。后者含节点比较和受控下载，不能当作单节点空闲场景。本版不会用早期通过覆盖复发结果，也不将局部性能基准当作端到端修复验收。

UDP/QUIC、休眠唤醒、网络切换及全部应用仍需专项验收。诊断中发现的订阅更新任务来源尚未确定，本版不将这一现象标为已修复，也不将未发现回环当作已排除全部间歇故障。

首次安装推荐使用 `magicnet_installer.zip`，需要离线安装时使用 `MagicNet-full.zip`。已支持模块更新的版本可在 WebUI 概览中更新；旧版本也可使用真实模块管理器安装。`MagicNet-component-*.zip` 是组件载荷，不是独立可安装模块。安装完成后重启设备，再检查实际版本、运行状态与联网结果。
