# MagicNet v1.9.0

本版精简日常导航和概览页，补齐当前所选代理的真实联网验证与有界备用节点恢复，并处理代理核心退出后自有网络拦截规则的清理。

## 日常操作

桌面侧栏和手机底栏直接提供「概览、节点、订阅、应用」。其余页面通过「更多功能」进入，原有深链接和快速跳转继续可用。切换页面保留未提交的表单内容。

概览首先显示代理状态、启动或停止按钮，以及「检查网络」入口。节点和订阅可以直接打开；运行证据、内存、TUN/eBPF、热点与 Wi-Fi 设置按需展开。移除重复的分区导航和概览装饰性流量图，流量路径说明仍可在原页面查看；真实状态以运行详情和诊断结果为准。

保留浅色、深色主题与中、英、俄三种语言。运行状态未知时仍要求先读取状态，未就绪和联网异常继续显示实际结果；精简布局不改变写操作确认和错误处理。

## 核心退出后的网络恢复

以前，代理核心意外退出后，监控只记录暂停，可能留下仍指向本地 DNS 端口的转发规则。新版在确认核心已经停止后，复用正常停止流程清理 MagicNet 自有的 DNS、热点和路由资源。

清理与启停、配置操作共用互斥锁。核心重新启动、状态未知或锁忙时暂缓；失败保留证据并在后续本地检查重试。此过程保持用户的配置和节点选择，不自动重启核心，也不发送新的公网探测。界面继续区分代理运行状态与互联网连通性。

## 当前代理与数据面分别检查

联网检查直接验证当前所选代理能否完成 Google 和 Cloudflare 的 HTTPS 204 请求，并单独记录 mixed 入口的数据面结果。测试域名被路由到其他代理时，其成功不会覆盖当前节点的失败。严格检查保留证书验证、禁止重定向，旧延迟测试响应也不会被误认为真实 204。

## 有界备用节点恢复

满足连续失败、直连可用和冷却条件后，自动恢复最多检查三个同组已有真实代理。候选通过双站点验证后，先确认保存成功，再切换并复验实际路径；保存失败立即报错，切换或复验失败则补偿原运行值和保存值。若期间出现新的外部选择，恢复流程保留新选择并报告冲突，不擅自覆盖。

## 立即检查与真实回执

概览的“检查网络”打开诊断页；需要跳过旧缓存时，可运行人类命令 `cli connectivity check` 取得一次新结果。节点切换后由受控探测流程及时复验。普通刷新继续读取缓存，人工检查只做探测并设 10 秒节流，不清空恢复动作冷却、订阅刷新间隔或 TUN 恢复次数。节点选择保存失败、严格探测能力不足和数据面异常分别显示，避免操作完成却被写成“已联网”。

## 安装与验收范围

在线安装使用 `MagicNet-core.zip`、`MagicNet.zip` 或 `magicnet_installer.zip`；完整离线安装使用 `MagicNet-full.zip`。下载后可用本发行的 `SHA256SUMS` 核对文件。

正式发布沿用固定源码构建、完整质量检查、Android/KernelSU 模拟器生命周期和网络恢复验证、最终安装包核验。模拟器、宿主回归与物理手机的结果分别记录。旧版设备现场诊断与配置恢复、新核心隔离实测、源码验证及正式发布门禁分别记录，详见[本轮验收记录](../connectivity-recovery-2026-11-18.md)；只有对应实际结果才能作为该范围通过的证据。
