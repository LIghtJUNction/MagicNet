# 运行时边界

## 单一写入者

WebUI 和 hooks 应只发送机器请求；配置文件、启动/停止、恢复由业务引擎处理。写操作持有固定 inode 的原生 flock。停止通过一个短时的独立意图锁持久化 STOP、取消正在下载的订阅，然后释放意图锁再等待主写锁。启动在排队前记住 STOP 版本，取得主锁后只允许清除同一版本的停止意图；后来提交的 STOP 不会被旧启动请求抹掉。不能 unlink 一个活锁。只读查询不创建状态目录，不自动恢复，不调用人类命令作为降级。

请求包含 `schema: 1`、随机 128 位 `id`、`method`、`expected_revision` 和 `params`。同一 ID、同一请求在记录保留期间返回原结果；不同请求复用 ID 被拒绝。历史保留有界，不承诺永久 exactly-once。`operation` 的 `params: {"id": "原请求编号"}` 查询指定回执；空参数仍查询最近操作。查询不创建目录、不补写回执、不恢复事务。未找到回执不表示操作失败，也不授权自动重试。

## 配置事务

完整旧值、新值和摘要先持久化，之后发布 prepared journal，再逐文件替换，最后发布 committed 标记。恢复先验证所有证据再回滚；不认识的文件、损坏的摘要或外部改写会保留证据并报错。故障注入覆盖 Store 层每个修改前后，不等同于模拟所有文件系统断电语义。

订阅更新只允许导入节点。路由、监听器、文件路径和认证配置不能来自远程订阅。多来源刷新全部成功后才一起提交缓存；删除来源会删除相应缓存，本地导入独立保留。Clash 转换目前只覆盖代码中列出的协议/传输，不能宣称支持所有订阅格式。

## 生命周期

生成不可变候选配置并由安装的内核校验，然后记录切换意图、停止原进程、启动候选、观察存活，最后提交运行指针。失败恢复旧代。停止优先于旧配置恢复；不确认归属的进程不允许被杀死。超时不对数据面使用 SIGKILL。

候选进程由原生 supervisor 持有，通过同用户 Unix socket 控制、代际租约和发布前门闩约束启动，子进程在 supervisor 意外死亡时收到清理信号；日志和代际保留有上限。宿主机测试使用不会修改网络的假内核验证这些机制。service、boot-completed 和 action 先检查管理器 disable/remove 标记，避免恢复流程重新拉起已禁用实例。

**仍有阻塞项：** native readiness 只证明短时间进程存活，内核/DNS 所有权清理、Android 进程与网络竞争以及完整内核兼容性未验收。不能把上述宿主机测试等同于真实安卓网络恢复。

## 界面

四页分别回答“正在发生什么、节点从哪里来、连接如何配置、失败如何处理”。保存不等于应用。订阅更新失败不清空输入；配置冲突保留草稿；跨页未保存输入不会被另一个保存操作暗中覆盖。没有 NativeBridge 时不伪造正常状态。重要状态不依赖颜色单独表达。响应丢失时，只保存请求编号和方法，不把链接、配置或导入正文写入浏览器存储。界面按原编号查询回执，未知结果阻止普通写入，不自动重发；停止和显式恢复仍保留入口。有效的后端失败与根本没收到有效结果分别处理。

## 尚未迁移的契约

候选版已经发布最小 `.state/machines/runtime.state` 投影和独立目录的 hooks/安装器。升级只复制稳定、已停服来源的私有意图；活动进程、未知归属、未完成事务和切换日志会阻止复制，原证据不变。原生产版完整机器协议、旧数据迁移、MCP、加密备份、Tailscale、热点/Wi-Fi、OEM 网络诊断仍未完成移植。原生产测试不能直接删掉、改为跳过，或用当前较小的宿主机测试集代替。
