# MagicNet

Сборка доступна через [Build and release MagicNet](https://github.com/LIghtJUNction/MagicNet/actions/workflows/release.yml) на main. По умолчанию mode=build сохраняет установщик, автономный модуль, компоненты и контрольные суммы; mode=publish требует новой версии ПО, согласованных update.json и заметок к выпуску. Старые версии не перезаписываются. Сборка и проверка Android используют один фиксированный коммит исходников; публикация черновика возможна только после всех проверок, включая хеши загруженных файлов. Это не подтверждает работу на реальном устройстве arm64 или в реальной сети. Обычный push не запускает тяжёлую сборку; PR проходят лёгкую проверку рецептов.

Рабочая среда прозрачной сети для Android с root, описанная воспроизводимыми программными рецептами.

[简体中文](README.md) · [English](README.en.md)

Проект и основной репозиторий сохраняют название MagicNet. Основной материал — рецепты в `recipes/`. [generated/magicnet-android/](generated/magicnet-android/) — Git-подмодуль отдельного [репозитория исходников magicnet-android](https://github.com/LIghtJUNction/magicnet-android), закреплённый на конкретном коммите. Имя репозитория и каталога совпадает и использует строчные буквы и дефисы. Исходники не входят в архив рецептов и не являются зависимостью Recipkg. Материалы наблюдения хранятся отдельно; временный каталог android-reference удалён.

Начните с [главного рецепта](recipes/magicnet/BUILD_PROMPT.md), [приёмки](recipes/magicnet/ACCEPTANCE.md), [источников](recipes/magicnet/PROVENANCE.md) и [измерений](recipes/magicnet/PERFORMANCE.md). Сохраняются возможности Android root/arm64, режимы tun|ebpf и языки; агент выбирает язык реализации и обновляет внешний вид без изменения рабочих сценариев.

`recipkg check recipes/magicnet` проверяет рецепты. `pack` создаёт во временном каталоге Markdown-архив с зависимостями; затем проверьте архив и используйте `build` для полной инструкции агенту. После проверки удалите временные файлы; постоянный архив сохраняйте только по явному запросу. Это не подтверждает независимое восстановление или работу сети на устройстве. Реализация v1.8.0 доработана по новым рецептам на основе прежнего кода. Main отслеживает подмодуль исходников; прежние теги выпусков остаются в MagicNet. Проверки пакета и устройства учитываются отдельно в VERIFICATION.

Секреты остаются локальными. При публикации сохраняйте существующие topics и добавляйте recipkg. Лицензии сторонних компонентов действуют отдельно.

## Кандидат независимого восстановления

Ветки `rebuild/recipe-0.3.1` содержат новую реализацию, созданную в пустом каталоге и новом контексте: контроллер Go, WebUI на нативных ES modules и Android Java bridge. Повторно используются только явно разрешённые фиксированные ядро и данные правил. Эта ветка закрепляет исходный коммит `b22f9f280ddaf729da47078c13838a73e6d89294`. Версия кандидата — **v1.8.1 / versionCode 10609**, версия рецепта — **0.3.1**. Проверки хоста, восстановления после сбоев, пакетов и кросс-компиляции Android отделены от приёмки на реальном устройстве и в реальной сети; см. [VERIFICATION.md](recipes/magicnet/VERIFICATION.md).

Фактическая фиксированная инструкция содержит 335 805 байт, 8 пакетов рецептов и 53 Markdown-файла; SHA-256: `502e160a363ffdc6e60477261ac15b74884b07f37de78af69558b0806f8e717a`. Контракт выпуска M40 появился на main после фиксации этой инструкции. Он сохранён в текущем рецепте, однако вновь созданная инструкция отличается от входа данной сборки. Перед интеграцией новой реализации в основной процесс выпуска необходимо адаптировать и пройти проверки M40. Официального выпуска Android и установки на устройство не было.

Для сборки кандидата инициализируйте `generated/magicnet-android`, перейдите в этот каталог и выполните `python3 scripts/fetch-build-inputs.py`, `bash scripts/build.sh all`, затем `python3 scripts/verify-package.py`. Полный автономный пакет — `dist/MagicNet-full.zip`; сетевые компоненты кандидата пока не опубликованы как официальные Release assets. Подробности — в [README новой реализации](generated/magicnet-android/README.md).

## Прежняя реализация на main

Для прежней реализации используйте новый `git clone --branch main --recurse-submodules https://github.com/LIghtJUNction/MagicNet.git`, перейдите в `MagicNet/generated/magicnet-android` и выполните `kam build -j 2`. Сохраняйте имеющиеся локальные изменения. Прежняя реализация требует Rust/cargo-ndk, Android NDK, Go, Node/npm, Java/d8 и KAM; см. [закреплённую инструкцию сборки](https://github.com/LIghtJUNction/magicnet-android/blob/b0bfe8b9f2fccdc4cbb46f5f0091a2d94694afc7/docs/build.md). Эти требования не относятся к новой сборке Go в данной ветке.

Коммит исходников `0dca28dd984d82333707cbf4b222596934b4d847` имеет то же дерево Git и шесть вложенных подмодулей, что и исходный коммит v1.8.0 `f13ca61b9c3477aee3b1380d71815c84b3a2a6bf`. При передаче кандидата main сохраняет коммит `b0bfe8b9f2fccdc4cbb46f5f0091a2d94694afc7`, включающий ещё не выпущенные исправления подписок и параллельные изменения процесса выпуска; прежняя история сохраняется в MagicNet. Сначала отправляйте разрешённые изменения исходников, затем обновляйте gitlink основного репозитория. Текущий выпущенный Android: v1.8.0. [Установка и изменения](docs/releases/v1.8.0.md).

Рецепт 0.3.0 уточняет поведение закреплённого v1.8.0 для issue #426: несколько подписок, идентичность источников, совпадение имён узлов, диагностика пакета, обратное чтение UI, сохранение VLESS Encryption и имена установщика. См. [проверку исходников](recipes/magicnet/SOURCE_AUDIT.md). Для check/pack/build достаточно полного Markdown-рецепта без старых исходников; независимое восстановление начинается в пустом каталоге. Рецепт 0.3.1 уточняет точный источник данных правил, полный контракт идентичности узлов и обязанности интеграции. Исправления исходников, независимое восстановление и проверка на устройстве учитываются отдельно; новый выпуск Android не заявлен.
