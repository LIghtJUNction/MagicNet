# 设计方向与证据边界

## 已观察的原产品

从源文件观察到暖纸色、墨色文字、陶土强调色、虚线星座图形、系统字体、主题 token、移动分组导航和桌面侧轨；实际打开了生产构建的预览页，确认导航、品牌、语种控件与概览层级。浏览器不连接真机，不能把预览当作设备 UI 验收。

## 用户确认的新方向

保留工作流，重做视觉并避免通用 AI 模板。以下是重建的设计约束，不声称是已完成的新 UI：
- 以“Android 网络仪表”为主张：一眼看清实际流量边界、当前模式、阻塞原因和下一步，而不是先摆四张统计卡。
- 将当前运行状态、用户意图、正在进行的事务和最近失败分出明确层级。未知使用文字/图形语义，不仅换灰色圆点。
- 密集的节点/应用/规则用可筛选行或列表；配置编辑器给正文空间；连接图只展示已证实链路，不造实时吞吐或世界地图。
- 可重新选择字体、主色和布局，但保留 MagicNet 名称/身份；用统一 token 管理语义色、字级、间距和动效。色彩是状态辅助，不能独占含义。
- 正常、空、加载、错误、拒绝、pending、回滚和恢复中均有具体内容。弱网时保留足够上下文，成功提示不遮挡下一操作。
- 窄屏优先让任务正文可用，复杂诊断按需展开。320/360/390/430、横屏 844×390、桌面 1280×900 都检查；键盘弹出后输入和提交按钮不能被底栏挡住。
- 默认可触达控件至少约 44px，有明确 focus；对话框 trap focus、Esc/取消与焦点恢复正确；支持 skip-to-content、语义标题、对比度、屏幕阅读器与 reduced motion。
- 不套紫蓝渐变/玻璃卡/营销 hero/虚构图表的默认组合；装饰动效不得延迟核心状态或操作。

## 路由编辑走查补充

Issue #413 的使用者并非只需要把现有节点切换入口改成中文：反馈明确要求无需手改 sing-box JSON，能按应用/域名指定出口，并创建自己的策略组/出口。路由工作区应让常用目标“应用、域名、出口”形成一条可预览流程；内置类型显示中文“代理/直连/拦截/自动测速”，保留并可搜索底层 tag。新建/编辑使用结构化字段与即时校验，密码等字段遮蔽；候选变更需展示影响的规则与目标，保存走已有配置事务并能恢复。不得用整段覆盖 route.rules/outbounds 的方式抹掉订阅和系统托管项。

新视觉的截图、字体许可、触屏与真机 WebView 表现均待未来重建实际验收。当前归档没有新设计图或实现。
