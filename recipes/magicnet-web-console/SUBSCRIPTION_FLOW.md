# 订阅界面的完整操作合同

版本：magicnet-web-console 0.2.1；提取日期：2026-10-29（Asia/Taipei）。本文件补齐现有十四页产品中的订阅工作流，不能据此删减其他页面。源码证据固定为 `LIghtJUNction/magicnet-android@0dca28dd984d82333707cbf4b222596934b4d847`，Android 产品标记 v1.8.0。

本质是把用户编辑的一组来源完整传到设备，等设备校验、合并并提交后，再显示那一次操作的结果。语法合格、成功投递、下载成功、核心激活成功分别是不同事实。

## 证据与重建目标

- **源码已确认，运行未验证**：以下表单、私密载荷、草稿和后台确认规则来自实际调用链，不仅来自 README。源码路径仅用于复查，不是构建者的输入依赖；所有必要行为在本文件内展开。
- **重建修正要求**：统一不同入口的 URL 身份、明确来源计数依据、补齐多源失败与用量缺失验收。它们不表示旧版本已经具备该正确行为。
- **Issue 报告**：[#426](https://github.com/LIghtJUNction/MagicNet/issues/426) 称多个订阅各自可用、一起不能拉取；附带状态却只记录一次 `configured_count=1`、`source_count=1`、`imported_count=60` 的成功。没有原始候选集合、失败阶段或可复现输入，不能判断失败发生在编辑、保存、拉取、转换还是激活，不能将下文发现直接认定为该 Issue 的根因。
- **尚未证明**：Android 原生桥实际多源操作、用户真实服务商响应、各 root 管理器、重建后的视觉与端到端网络结果。已有源码测试与模拟 E2E 定义不是本轮真机证据。

根包提供唯一 control/runtime 合同，本包不重复引入它们作为依赖。公开命令、设备侧来源身份、合并和回滚以那些合同为准；本文件补齐如何表达用户意图以及如何消费结果。内部页面名、框架、函数和定时器实现可以改变。

## UI-SUB-001：从设备配置建立编辑基线

**源码行为。** 无来源时直接显示编辑器、每行一个 HTTPS URL、最多五个的说明，以及粘贴、导入文件、添加并启用动作。已有来源时显示来源概况、管理来源、更新订阅和重新读取按钮；管理来源展开编辑器、滚动到可见位置并聚焦输入。关闭编辑器时若焦点在其中，回到管理来源按钮。

配置通过本地私密 `cli --json sub inspect` 回读。只接受 `schema=1`、`ok=true`、`command="sub.inspect"` 且结构一致的响应；远程模式的 `source.configured_count` 必须与 `configuration.sing_box_urls` 长度相同，本地模式 count 必须为 1。URL、User-Agent、过滤词是用户自己的本地可编辑配置，可以存在编辑器内存；不能因为公共 status 的隐私限制而把它们删除、清空或改成无法编辑。

读取失败时明确未知并保留用户草稿，不能用空默认值冒充“没有来源”，也不能根据旧成功状态显示本次任务成功。新的只读回读不能把过时响应覆盖到后来一次请求的结果上。无原生桥时明确预览，不能真正投递写任务。

## UI-SUB-002：完整的多行输入与唯一来源身份

**源码行为。** LF、CRLF、单独 CR 均分行；去每行两端空白和空行。拒绝非 HTTPS、含 userinfo、内部空白或无法解析的 URL。任何无效行阻止整个提交，用户可原地修正；不能只提交剩余有效行。只接受 1–5 个唯一来源，六个时整体拒绝且保留全部草稿，不自动截断为五个。重复项提示数量，去重保持首次出现顺序。“去重并整理”只修改草稿，不发起下载或保存。

**重建修正要求。** UI、CLI、持久配置、缓存身份、私密回读和下载器使用 runtime 的同一规范化规则，不能分别再次解释原文。scheme/host 小写、默认 HTTPS 443 省略、空 path 记为 `/`；fragment 不发送给服务商、不作为网络来源身份，移除时给用户可理解提示；path 大小写、query 参数顺序/重复 key 和已有百分号编码字节保持不变，不能解码再编码签名 query，不能把 `%26` 解成分隔符、把 `%23` 解成 fragment、把 `+` 改成空格，不能把同主机但不同 path/query 的来源合并。其余 URL 边界由 runtime 合同明确规定并统一验收。旧缓存只有完整来源身份可证明一致时才能迁移；不能按 hostname 或行号套用旧缓存，无法证明时显示未知并重新拉取。

例如下列前三行代表两个网络来源，第四行和第二行相同：

~~~text
https://EXAMPLE.invalid:443/feed?token=alpha%26beta&format=singbox#client-note
https://example.invalid/feed?token=alpha%26beta&format=clash
https://example.invalid/feed?token=alpha%26beta&format=singbox
https://example.invalid/feed?token=alpha%26beta&format=clash
~~~

最终候选为 singbox、clash 两条，按首次出现顺序；不得变为一个主机或一个 token。示例仅作离线输入夹具，`.invalid` 不用于实际下载。

~~~text
输入：https://EXAMPLE.invalid:443/Feed?x=%2f&x=%2F&x=a+b#note
候选：https://example.invalid/Feed?x=%2f&x=%2F&x=a+b
输入：https://example.invalid
候选：https://example.invalid/
~~~

`/Feed` 不能改为 `/feed`；三个 `x`、其顺序、`%2f` 与 `%2F` 的字节差别以及 `+` 均保留。

基线源码 `0dca28d` 的 UI 使用浏览器 URL 序列化后去重且保留 fragment；同一基线的 Rust 文本入口按 trim 后的原串去重，旧下载路径又移除 fragment。这个不一致是提取发现，不能照抄成重建合同。

## UI-SUB-003：检查来源与私密摘要

**源码行为。** 预览逐行列出序号和 `ok|duplicate|invalid|over-limit`，只显示 scheme/hostname，并隐藏 path/query/hash。摘要含原始行数、有效行数、重复数、超限数、可保存数、无效数、HTTP 行数与状态；复制结果不得包含完整 URL、原始响应、凭据或载荷路径。

**重建修正要求。** 将“有效”解释为“URL 格式有效”。本地语法检查和可选域名解析不能被描述为服务商验证、订阅导入、代理可用或本次激活成功。已配置数、当前草稿数、本次尝试来源数、成功导入来源数和导入节点数分开展示，不能复用一个数字给不同意义。

预览显示限制不能变成保存限制：旧 UI 最多展开前八条预览，隐藏条数仍须可见；所有行参与校验。公共诊断优先保留序号、计数、阶段和规范错误码，只有用户的本地来源编辑区可显示来源域名等私密关联信息。

## UI-SUB-004：私密载荷完整传输

**源码行为。** 点击保存时立即冻结当前规范化来源列表和编辑修订号，再执行任何异步读取。URL 列表以 UTF-8 换行文本传入设备受控私密 payload；最后一行有换行。不得把用户输入直接拼接到 shell 命令、预览或日志。传输可分块，但 UTF-8、多字节字符、换行、`&`、`?`、百分号编码、引号和反斜杠不得因桥接而截断、展开或变成额外命令。

既有对外兼容命令为 `webui payload create|append|remove subscription <basename>`，append 的数据为 base64；URL 激活使用 `webui payload apply-subscription <basename>`，本地文件使用 `webui payload apply-subscription-source <basename>`。只接受设备返回的单行受控绝对路径。本 UI 生成的安全文件名以英数字开头，其后只含英数字/点/下划线/连字符，最长 128 个 ASCII 字节；后端既有入口还兼容 `_` 或 `-` 开头，只禁止点开头，不因本 UI 的命名选择收紧该公开兼容范围。目录或文件不符合私密普通文件要求时失败；不能跟随软链接、硬链接或任意路径。

任何 create/append 失败都禁止进入 apply，并尝试清理同一 owner 的私密文件。投递失败也清理；清理未确认时只报告规范化告警，不把残留路径或内容暴露到共享输出。设备消费 payload 后按控制面约定移除，不能为重试公开保留用户订阅内容。传输校验应比较规范化候选的全部字节和来源顺序，不仅检查第一个 URL 或命令名称。

## UI-SUB-005：保存、接受、完成与生效

**源码行为。** 初次配置动作为“添加并启用”，修改现有配置为“保存并应用”；没有实质变化时不能重复提交。通过背景任务执行，先取得已知设备基线，否则不发起激活。成功投递只显示“已提交，验证通过后生效”，不能立即关闭为成功。

**同次完成合同。** 必须确认该任务被接受、对应执行者真实退出且退出状态成功，并取得较提交前更新的设备尝试/生成标识和 `last.result=success`。没有新的尝试或生成标识时，旧 `success` 不能完成新任务；poll 读取失败不能借用旧快照。多源激活成功还必须与提交的来源集合、顺序及模式一致，必要的失败来源信息由运行时的规范状态提供。仅收到本地 bridge 完成、命令已接受或域名可解析都不能满足这些条件。

重建还必须用本次受控 task/operation 回执证明 generation 确实属于这次提交，不能仅凭最新代次或数量相符认领另一个 CLI/MCP 的结果。无可信绑定时匿名显示批次，保留草稿并提示核对，不把“有新success”当作自己的保存完成。订阅已提交但 selector replay 失败沿用退出码0+独立警告；batch 为 committed、error_code=none、warning_code=selector_replay_failed，显示“订阅已提交，选择恢复待重试”，不能误报回滚或重复提交。

下载、解析、合并、核心检查、激活和状态回读失败分别给出可执行下一步。保留草稿和原有有效配置，并显示实际阶段或未知；不能把失败显示成“只导入一个来源也算成功”。允许带缓存回退的条件及全失败/部分失败策略由 runtime 唯一规定，UI 必须准确显示该策略的实际结果。

新增批次观测按 control 的 `SUBSCRIPTION_INTERFACE.md` 协商 `subscription_batch_v1` 后消费 `last.batch`；它是本轮重建目标，不是固定源码现有能力。未协商或旧响应缺少该字段时显示“来源级结果未知/当前版本不提供”。已协商但从未接受更新或升级后没有历史批次证据时允许 `last.batch=null`，显示“尚无可用批次记录”，不能制造代次、空成功或逐源完成。不能从节点数、域名检测或旧成功推导每个来源成功。本包不另造公共 schema，也不把私密 inspector 全量透传到公共状态。

`batch.requested_count` 是控制面**实际收到的候选文本**按合同去掉空行后（控制面不接收注释行）、后端去重前的条数，不是 UI 编辑器的原始行数。当前 UI 会先规范化去重再传输，因此它可能等于 `batch.unique_count`，而小于编辑器的 raw；UI 自己的 raw、重复数、提交数必须分别保留和标注，不能要求设备还原未曾传入的重复行。

批次的 `sources[].index` 指向那一代次的候选集合，当前 `source.configured_count` 和 inspector 配置指向已提交集合，失败时两者可以不同。只有持有**同 generation 冻结候选**的本地编辑会话才能把 index 映射到具体来源；重开页面、丢失候选或代次不匹配时显示匿名“候选来源 2”及规范阶段，不把失败的 A+B 批次套在仍为 A 的旧配置或后来草稿上。旧配置数量仍显示 1，本次候选数显示 2，不把这种差异称为状态矛盾。

## UI-SUB-006：并发、超时与草稿保护

**源码行为。** 一个写任务未真正结束前不启动另一个冲突写任务；UI 超时和投递确认超时都不等于设备取消。继续以有界频率对账，显示“仍可能在后台进行”；晚回调不能覆盖新操作，真实退出前不能提前释放原生执行槽。旧实现先较快轮询、长时间未确认后改为每 15 秒继续检查；重建可以改内部调度，必须保留单一在途观测、可读状态和无重叠写的外部行为。

保存 B 后继续编辑 C，再收到 B 的成功回读：设备基线更新为 B，编辑器保留 C 和未保存标志，不关闭编辑器。只有回读与提交快照、来源模式和修订号匹配，且用户未继续编辑，才清除 pending 并同步/关闭。失败回读保留草稿；取消编辑恢复最后已知设备基线，不更改设备。

本地文件导入要求确认 `source_mode=local` 及新生成标识；空 URL 列表本身不能证明导入完成。切页、语言切换不能丢弃内存草稿；关闭 WebUI 后设备任务依 canonical 状态继续恢复，不能依赖旧页面内存证明完成。草稿不写入 localStorage。后台任务仍运行时的“取消编辑”不能暗中成为取消设备任务。

## UI-SUB-007：来源数与服务商用量

**源码行为。** 用量只取服务商订阅元数据，不能用设备流量累计代替。每个来源记录身份、序号、hostname、`fresh|cached|unknown`、上传/下载/额度字节、过期和更新时间；身份与序号冲突的元数据不能猜测归属。URL 和用量来自同一次受控 inspector 观测，不能按编辑器当前行号给旧用量重新贴标签。

计数非负且为安全整数，缺失/负数/小数/溢出为未知。已用 = 上传 + 下载（两者都有效且和不溢出）；额度 > 0 时剩余 = max(0, 额度 − 已用)，比例上限 100%。额度为 0 是“未提供额度”，过期为 0 是“未提供到期时间”，不能显示无限套餐。缓存标“上次用量”，过期/用尽与未知分开。超过 90% 或剩余不超过三天可提示警告；不能因这些显示提示自动删除来源。

**重建修正要求。** 来源总数以已确认的配置集合为准，不能取有用量记录的行数。两个已配置来源中只有一条 metadata 合法时仍显示两个来源；缺 metadata 的来源保留未知行，不复制另一来源的数字。重排来源不串账，已删除来源不从缓存复活，本地来源模式显示一个本地来源且没有远程套餐信息。

基线源码 `0dca28d` 中页面总数来自 `usageRows.length`，而非空但不完整的 metadata 可导致 overview 只生成部分行。这是需要补验收的展示风险；不能据此推断 #426 的设备配置被截断。

## UI-SUB-008：本地文件与远程来源切换

**源码行为。** 允许选择 `.yaml/.yml/.json/.txt/.list/.conf` 等文本文件；文件扩展名只用于选择，不证明有效内容。空文件、仅空白、非 UTF-8、NUL 字节和超过 8 MiB 的输入明确失败。内容可为 sing-box JSON、Clash/Mihomo YAML、分享链接或编码文本；格式探测标签只是预览，最终可用性由设备解析和核心检查确定。

导入时保持当前远程来源及有效核心配置，直到本地候选整体验证并提交；远程 URL → 本地 → 远程双向切换均须回读相应模式。选择文件后可再次选择同一文件重试；取消文件选择无副作用。文件内容不上传外部转换站。所有 size 检查按实际 UTF-8 字节执行，末尾换行处理也不得令实际传输突破设备上限。

协议字段的完整性也属于导入成功条件：如 VLESS 的 `encryption`，应按 engine/runtime 的已定义语义原样保留并校验，不能静默剥离后宣称兼容。专用编辑器可私密读写完整值，不应用节点显示名的短长度限制截断密码学参数；转换格式不能表达必需字段时明确不支持或失败，不能让 UI 把丢字段的节点计为可用。真实握手仍需端到端验证。

## UI-SUB-009：移除来源的独立语义

**源码行为。** 已配置情况下把草稿清空，按钮变为“移除所有来源”；必须经过明确确认，取消无写入。确认后使用 `sub clear` 移除来源链接和本地源文件，**保留当前核心配置且不重启核心**，不能把“移除订阅来源”做成断网或清空全部节点。

清除失败保留旧来源和草稿；写已成功但回读失败时区分“已移除但状态读取失败”，不伪造已确认空状态。清除后的来源概览不能被旧用量缓存重新填充；此时“更新订阅”不应启动无来源任务。

## UI-SUB-010：User-Agent、过滤与周期设置

**源码行为。** User-Agent 先 trim，最多 256 UTF-8 字节，不接受控制字符；空值使用下载器默认。预设映射固定：默认→空串、sing-box→`sing-box`、Mihomo→`clash.meta`、Clash for Windows→`ClashforWindows`、Shadowrocket→`Shadowrocket`、v2rayNG→`v2rayNG`。提供自定义值、当前字节数和就地错误。保存来源前若有修改的 UA，先保存并回读；失败则不投递来源激活。UA 与来源不是一个原子提交的事实必须诚实呈现，不能声称后续订阅失败就已撤销 UA。

过滤词最多 32 个，每项最多 64 UTF-8 字节，trim、去空、按英文大小写不敏感去重；提供免费/free/HK/香港/TW/台湾预设。新安装默认过滤说明必须可见，清空保存即关闭过滤。已配置时保存 UA/过滤词后触发订阅重建；保存成功与刷新成功分别反馈。提交过程中继续输入的新草稿不能被回读覆盖。

周期只允许 `off|12|24|48|72` 小时；配置启用、进程实际运行、owner 有效性分开。启用但 owner stale/none 时即使周期不变也允许重存以恢复；unknown/pending 提示重新读取。休眠、重启或正在执行的任务可能推迟更新，不能承诺固定墙钟时刻执行。

## UI-SUB-011：隐私、错误与状态完整性

本地私密 inspector 允许用户编辑自己的完整来源；公共 `sub.status`、MCP 自动资源、支持包、操作捕获、最近输出和 Issue 草稿不应包含 inspector 原文。错误只带规范错误码、阶段、序号/计数，不附原始 URL、响应正文、节点凭据、私密载荷或 token。

私密回读静默执行；命令历史仅显示脱敏操作类型。坏 JSON、多 JSON、错误 envelope、计数矛盾、非法所有权组合均不能拼凑成成功。来源列表、用量、上次结果应来自一致快照；发现不完整时显式未知并保持可重新读取，不静默借用旧数据补成绿色成功。
