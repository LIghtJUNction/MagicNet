# 软件质量合同：设计、美学、代码与性能

重建目标软件时，将本配方作为可复用的质量基线。根软件配方负责说明产品行为和用户目标；本配方提供跨项目质量要求。具体项目的用户要求和仓库规则优先。遇到冲突时列出冲突与影响，不暗中选择。

## 视觉与交互设计

仅在软件有 UI、TUI、文档网站、可视化输出或其他面向人的呈现时应用视觉要求；CLI 和 API 也要做到信息层次清楚、命名一致、错误可理解。

### 先理解，再设计

- 先确定目标用户、核心任务、信息层级、运行环境和品牌气质，再选布局、字体、颜色、组件与动效。设计服务于内容和任务，不从流行组件模板倒推产品。
- 阅读项目现有设计文件、组件、资源与同类真实产品。保留已有的有效视觉语言；全面改版必须有明确目标和验收，不因“看起来更现代”而重做。
- 用户提供参考时，提炼其层级、密度、色彩、排版、交互和气质；不要复制品牌、文案或未经授权素材。
- 信息不足但不影响实现时，作出小范围、可解释的设计决定；品牌方向或关键交互确实无法推断时，将少量问题合并询问。

### 建立有辨识度的设计系统

- 为产品选择一个与其用途相符的视觉主张，并保持页面和状态一致。明确颜色角色、字体层级、间距尺度、网格、边框/阴影、图标风格和动效规则；用设计 token 管理跨组件复用的值。
- 让信息层级由真实重要性决定。避免把所有内容做成等权卡片、同尺寸标题、无意义图标和每屏一致的后台模板。
- 文案使用具体、自然、符合产品语境的表达；禁止 lorem ipsum、重复占位文案、虚构数据和无意义营销句。
- 选用清晰可读的字体和可访问的颜色对比；验证键盘操作、焦点、错误、禁用、加载、空状态、成功状态和窄屏布局。
- 动效只用于解释状态变化、层级或空间关系；尊重减少动态效果偏好。不要为了装饰拖慢交互。

### 避免模板化的 AI 视觉痕迹

下列模式不能作为无思考的默认答案：紫蓝渐变、玻璃模糊、大圆角白卡、渐变大标题、英雄区加三张 feature card、虚构 dashboard 图表、彩色 emoji 图标、到处相同的 sidebar。只有符合产品任务且经过整体设计时才采用局部模式。

不要靠堆叠阴影、渐变、圆角、动效或组件数量伪造完成度。交付前检查实际页面：删掉装饰性噪声，确认版式是否体现当前产品内容，检查关键状态和多个屏宽。若环境可运行 UI，实际打开并检查，不以代码能编译代替视觉验收。

## 代码品味

- 以清楚、可读、可预测为默认；沿用代码库现有命名、目录和格式约定。先找到正确的领域边界和数据流，再写代码。
- 保持模块内聚、接口明确、依赖方向清晰。只有存在真实重复或稳定概念时才抽象；避免为了未来假设而建框架、工厂、配置层或泛化插件系统。
- 保持单一真相源：同一个业务规则、配置、数据或设计 token 不在多处手工复制。派生状态能计算时避免重复存储；需要同步的生成文件标明来源和更新方法。
- 让错误能定位、对用户可理解；显式处理输入校验、取消、超时、资源清理和部分失败。安全边界与权限不能藏在 UI 或隐式默认里。
- 不留下死代码、无用依赖、占位实现、吞异常、无理由的 TODO、调试输出或为了通过检查而削弱的验收。代码注释解释意图和非显然约束，不复述每行语句。
- 控制改动范围，不重写无关模块；公共 API、持久化格式和关键行为变化必须说明兼容性与迁移方式。

## 性能约束与测量

- 优先服从根配方中已定义的性能预算与目标设备/工作负载。常见指标包括启动/冷启动时间、关键操作延迟（如 p95）、吞吐、内存峰值、CPU/电量、网络请求数、前端 bundle/页面加载、数据库查询数和镜像体积；只测对产品有意义的指标。
- 若没有明确预算，不编造数值或承诺。先记录代表性 workload、数据规模、目标设备和当前基线；从用户需求、现有表现或目标平台限制推导候选预算，并将未确认的数值标为待确认。
- 对性能敏感的实现，在优化前测量基线，使用可重复的数据与命令；报告环境、预热、样本规模、统计口径（如 median/p95）和结果。区分真实测量、估算和推断。
- 避免显而易见的高复杂度算法、重复全量扫描、无界缓存、过度渲染、串行独立网络请求和无界并发。根据数据量、交互路径和平台约束选择算法、缓存、分页、批处理和并行策略。
- 优化必须保留功能正确性、错误语义、安全和可维护性；不要仅为微基准引入复杂抽象。先定位热点，再做最小改动并重复同一测量。
- 用项目约定的检查验证性能目标。没有稳定运行环境时，将性能验收标记为未验证，不以理论分析声称达标。

## 验收输出

交付时说明：采用了哪些根配方要求、怎样应用本质量合同、作出的重要设计与架构决定、代码组织理由、性能预算和测量环境、已运行检查、未解决冲突以及未验证项。视觉软件还应报告关键屏幕宽度和状态的实际检查结果（如果无法运行，明确写出）。
