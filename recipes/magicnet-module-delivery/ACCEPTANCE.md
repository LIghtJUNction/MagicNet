# 分发验收

0.2.9 增加报告门禁负例：错误源码、缺阶段/重复阶段、跳过、错误类型、重复 JSON 键、超限报告、核心身份变化、未真实删除规则、故障仍 ready、用 TCP 替代 RPDB 的 UDP 负控制、未绑定/清理接收端、未发请求、无独立网络归属证据却忽略外部规则变化、未恢复应用流量或配置。全部必须拒绝；完整真实模拟器报告才通过，宿主校验夹具不算设备流量证据。

发布计划回归必须覆盖旧 KAM changelog URL、旧 changelog_file 与缺失源码发布说明：三者均在构建前拒绝；一致元数据可通过。完整产物质量和 Android 门槛仍不可跳过。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| full、core+组件、旧版无 manifest、全复用 | 安装/升级 | 同一最终 runtime 文件与权限；full/复用不联网；保留订阅和用户配置 |
| 系统没有curl；生产ARM64包和AVD x86_64组件 | 核对bin/curl、固定源码/ABI/许可/CA证明与manifest，完成全包安装、组件安装及复用；实际执行版本、嵌入CA与TLS正反控制 | curl随正式组件提供，下载能力不依赖另装root模块；HTTPS/TLS/gzip可用且错误证书拒绝；使用同源构建器，测试专用注入不能替代生产供应；无新增常驻进程 |
| 只有 `lib/kamfw/` 的干净检出、安装引导、卸载临时会话；当前用户浏览器缺失、角色查询失败、ActivityManager 输出错误或超时 | 初始化固定依赖并执行启动器、安装和卸载回归 | 同一 `launcher.sh` 支撑两个入口，无 `lib/kamfw-web/`；当前用户选择及 BROWSABLE/Binder 回退正确；失败有界且退出码保留；原有 URL/app 调用兼容，导入及调用不污染调用者状态；gitlink 变更触发对应检查 |
| staging 完整安装后真实 rename 到最终模块目录，含自有缓存/checkpoint/last-known-good 与外部自定义路径 | 晋升后启动检查、恢复和再升级 | 自有路径解析到最终位置，不依赖已消失 staging；恢复内容保留；外部路径意图不被误改，不能只在未移动的测试目录宣称通过 |
| MagicNet-core.zip、MagicNet.zip、magicnet_installer.zip | 比较摘要/模块身份，再分别安装升级 | 三者逐字节相同、ID 都为 MagicNet；更新同一模块，不出现外层 installer 模块、嵌套安装或重复核心下载 |
| 未变组件只改 WebUI、改变 ZIP 顺序/时间戳 | 构建 | 未变组件 identity 不变，更新流量不强制重下核心 |
| 字节篡改/私网重定向/TLS 错误/磁盘不足 | 下载 | 校验前不激活，规范错误，旧文件保留 |
| 每个替换点强杀、恢复时 I/O 失败 | 再次安装 | 先恢复 journal，不能普通成功；恢复证据留下但空间有界 |
| zip-slip、重复条目、头部歧义、unsafe link、错架构/身份 | 安装/更新 | manager 运行前拒绝，用户目录不被写 |
| 同 ID、冲突 ID、4096 budget、receipt 过期、并发 | module-update | 幂等/conflict/busy/耗尽明确，不遗忘重放历史 |
| 成功回执存在后新增 pending、update/disable/remove marker、坏 journal 或另一任务 recovery_required；再对照健康同意图重放 | 重放历史 request ID | 在受控 owner 内先检查当前阻断，旧成功不能绕过；不启动新 worker、不覆盖原 ledger/恢复证据、不删外部 pending，健康同意图不重复安装 |
| manager exit0 但 staged 不符、有效 pending/disable/remove | install | 拒绝或 staging_unverified，不能误报新版本已生效 |
| reboot 前后、CLI hash不符、manifest缺失 | status | reboot_required/unknown/effective version 准确 |
| 真 manager 部分失败/被杀 | 恢复 | recovery_required，不擅删他人 staging，不自动重启 |
| 迁移清单中增加状态路径，只修改“备份”或“恢复”其中一边；再测试显式模板排除项、权限、复制失败 | 首次安装/升级 | 备份与恢复由同一清单派生，配置重建例外单独可审阅；遗漏不能 exit 0 静默丢数据；失败退出非零并留下可恢复证据 |
| 真实发布 ZIP 与 support canary | 包检查 | 无 .env/本地状态/密钥/日志/旧 TProxy资产；with_ebpf 元数据和所有摘要一致 |
| 模块根、配置子模块与框架依赖中存在 test/tests、fixtures、快照、benchmarks、coverage、node_modules 或空测试目录 | 运行真实 KAM ZIP 清理，再拆分核心/完整/组件包 | 按完整目录段递归排除；全部最终 ZIP 均不含禁用目录；源码测试继续保留 |
| `bin/test`、`rules/test.srs`、`test-support.sh`、运行配置、依赖运行代码和许可证 | 清理前后与最终完整包比较文件内容；重复清理 | 同名运行文件字节保留；第二次清理后的 ZIP 字节不变；清理删除失败非零退出 |
| 未清理测试目录直接交给组件打包器，或在最终核心包、完整包、任一组件中注入禁用目录后更新摘要 | 运行组件打包与最终发布验证器 | 两级检查均明确拒绝对应脏包；正确摘要不能绕过内容边界；不生成可发布的半套产物 |
| 主仓库只更新配方/固定源码，手动 build/publish、错误源码 SHA、错更新地址、既有标签、版本未递增、缺失/篡改资产、Android 失败或跳过 | 按 RELEASE_CONTRACT 执行构建发布 | build 不发布；全部构建/验收使用同一 gitlink；只向 MagicNet 正式发行；不覆盖旧标签；任一必需门槛或服务端摘要失败都不公开草稿 |
| 主仓库根 module.yaml 缺失、description/icon 引用失效、身份/架构或 release.assetPattern 与交付不一致 | 配方迁移、分支合并后的目录检查及发布前复核 | 文件与引用资源受跟踪且可解析；身份 MagicNet、官方仓库和 MagicNet-full.zip 一致；任一缺失或不一致明确失败，源码子模块中单独存在 manifest 不能替代主仓库入口 |
| 上传后的草稿标签查询 404、无匹配草稿、多个同名草稿、非法 ID、服务端摘要不符 | 读取并公开草稿 | 唯一数字 release ID 可继续核对；缺失/歧义/非法 ID 或错误摘要均不能调用公开操作 |
| 构建与 Android/完整质量已通过，仅发布控制失败 | 独立恢复原草稿 | 验证原 run、源码与配方提交及不可变 artifact，重新核对完整字节与服务端资产后按原 ID 公开；任一构建/验收失败仍拒绝；不替换附件或旧标签，单独记录恢复结果 |

这些是分发合同，不是当前轮次的执行报告。各次构建、manager、发布及设备结果按固定提交分别记录于根 VERIFICATION.md；0.3.2 新增目录晋升、历史回执和模块目录要求在取得本轮证据前仍为未验证。

## 归档门禁执行范围

源码中的 `scripts/test-artifact-cleanup.sh` 使用合成模块实际运行清理钩子和 `scripts/package-components.py`。当前夹具输出五个组件，加上核心包、完整包与两个别名，共 **9 个 ZIP、88 个条目**；逐包检查 CRC、目录边界、manifest 引用与运行文件字节，验收输出为 `Final archive inspection passed: 9 ZIPs, 88 entries`。这些条目是实际生成的 ZIP 成员，测试载荷不执行 Android 二进制。

源码 `scripts/test-component-archive-safety.py` 验证绕过清理的开发目录被拒绝，以及运行同名文件在最终包中保留。主仓库 `scripts/test-release.py` 覆盖核心包、完整包与组件的 18 组目录注入反例，并保留正常运行文件的正例。当前夹具规模用于核对本轮主机证据；生产发布的所有实际组件仍必须逐包检查，不以固定数量代替实际清单。


## 安装清理与突发 UDP 内存（2026-11-03）

更新和安装继续使用唯一、有 ownership 标记的事务目录；失败先恢复再清理，恢复失败保留唯一恢复材料。清理分批遍历，避免文件数量决定瞬时列表内存，不新增时间戳备份。UDP 索引达到 1024 项后，在最后一项释放时丢弃空索引的底层空间；小流量仍复用索引。保留分片锁、共享引用计数和旧连接不能删除新连接的规则。测试覆盖大批连接释放、重建及安装成功/失败/恢复/未知目录保护；记录性能与内存实测，不把微基准当作真机 RSS。接口和运行依赖不变。

## 0.2.3 目录收敛验收

新装、升级和复用构建均不存在 magicnet-network-card.svg；归档不含构建 .state、.cache、旧 .tmp/.local 状态。迁移覆盖空目录、嵌套目录、同名相同/不同内容、只读/失败、symlink、重复执行和中断恢复；保留已有用户意图与私密载荷，完成后只剩新的生产路径。

## 0.2.7 升级与 TLS 控制

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| core/full/installer 新装及旧配置整目录恢复，清单缺失或已自定义 | 执行实际 SKIPUNZIP 安装入口 | 缺失清单从同一 ZIP 补入；自定义字节保留；权限为 0600；暂存目录清除 |
| 清单或其父路径是符号链接/非普通对象 | 安装或升级 | 非零失败；外部目标不被改写，不以缺省清单覆盖用户对象 |
| 旧订阅历史存在/不存在，当前 .state 路径的 update lock 同时存在 | 真实打包安装升级 | 已记录历史原字节迁移，缺失历史不伪造；该 update lock 不随历史恢复，canonical 仍按当前运行证据生成 |
| 临时证书签发时刻、客体落后 120 秒、落后 600 秒、两天后 | 用真实 OpenSSL 验证指定时刻，继续真实回环 TLS 控制 | 正常与有限落后通过；超窗/过期仍拒绝；错误主机名和默认信任拒绝保持 |
| curl 非预期退出、返回成功但 GET 计数不符、时钟不可读、私密 canary | 执行验收与失败产物保存 | 退出和 GET 双证据不符均失败；保留固定诊断与清理状态；未知时间不伪造，canary 不进入产物 |
| 核心/API 已启动但数据面 unknown、支持包无效或下载失败 | 就绪超时后的失败收尾 | 复用有界脱敏支持包保存可用健康/路由证据；采集失败使用固定状态且保留原阶段错误；不降低就绪条件，不输出私密错误原文 |

受控时钟负例证明夹具的容差缺陷，不单独证明历史 Android 失败的唯一原因。主机测试、模拟器新 run 和物理设备结果分别记录。

## 0.2.8 发布流水线验收

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| stable updater 与源码不同版；none/patch/minor/major/自定义版本/code | 规划 build/verify/publish | 稳定索引滞后不阻止构建；冲突、非法版本、code 越界或发行回退在构建前拒绝 |
| source_ref 指定分支后继续推送；原 run 重跑 | 读取发布快照并构建 | 两个工作流始终使用首次解析的 SHA 和同一目标版本；不跟随更新后的分支 |
| 原始 main 提交、未提交计划、错 run/父提交/输入 | 尝试发布 | 拒绝冒充固定发行快照，不产生公开发行 |
| 原 artifact 上传中断、starter 空资产、错误摘要、不同 artifact 重建 | 重跑失败 job | 仅恢复原身份；正确已上传字节不变，补齐缺失项，限定空资产可清理；错误或混合产物拒绝公开 |
| 正式发行成功、预发布、索引同步冲突、main 已有更高版本 | 同步 main metadata | 正式发行才更新稳定 updater；预发布补入 notes；保留其他文件和 gitlink；不回退稳定版本 |

主仓库隔离 Git/API 回归、源码 metadata 注入回归和真实 Actions 运行分别记录；测试文件保留在开发树，仍禁止进入最终模块。
