# 单文件诊断导出

诊断的目标是在一个文件中留下足够关联证据，区分路由、DNS、sing-box 配置/特性/资源、订阅及恢复问题。报告记录各层实际观测与缺失原因；单次快照不能保证查明所有瞬时或历史故障，也不能把未运行的公网/应用测试写成通过。

## DIAG-001：入口与文件语义

人类命令 `cli support bundle` 输出完整脱敏文本；`cli support export` 将同一报告保存到单个文件。机器命令为 `cli --json support export`，规范名 `support.export`，只允许无附加参数的导出。Android 固定路径 `/sdcard/Download/MagicNet/MagicNet-diagnostics.txt`；宿主夹具固定到模块根 `.state/diagnostics/MagicNet-diagnostics.txt`。不让外部调用者传入任意特权输出路径。

`support.export` 是经过设计的机器写例外：capabilities 同时列于 commands/mutation_commands，并声明 `support_export={requires_write:true,state_effect:"export-only",fresh_network_probe:false}`。成功仍是单个 schema-1 envelope，data 仅含 path 与 bytes。写入失败非零退出，规范错误 `support.export_failed`，不泄露底层私密错误。拒绝未知参数，不落回人类 dispatcher。

同目录以独占创建、拒绝符号链接的临时文件收集，完成后同步并原子替换固定文件；Unix 权限为 0600，Android 共享存储受系统访问规则管理。失败保留旧完整文件；并发使用独立临时文件，最后成功完成的报告生效，没有半文件或散落附件。重复导出只保留最新完整文件，不积累无限历史。

## DIAG-002：范围与证据

| 证据域 | 最小内容 |
| --- | --- |
| 构建与平台 | 模块/CLI/核心版本、核心 build identity、Android SDK/系统版本/SELinux、内存/负载/运行时间 |
| 进程与生命周期 | 受控进程身份结论、RSS/线程/FD/调度/I/O、启动步骤、监督状态、事务阶段 |
| 联网与恢复 | 已缓存主目标与差异探测、失败原因、时间/退避、最近修复/刷新/重启动作及日志；无新外网探测 |
| 路由与 DNS | IPv4/IPv6 路由和策略规则、必要接口/监听信息、模块自有防火墙规则、DNS模式/状态 |
| 核心与配置 | 有界 version/check、入站/出站/DNS/路由顺序、类型、计数与引用关系、TUN/eBPF能力/实际状态、本地 API 证据 |
| 订阅与意图 | 已提交来源类型与数量、候选/刷新/缓存/转换/回滚证据、覆盖与用户意图的脱敏结构 |
| 日志 | 相关模块日志尾部及明确的缺失/超时/截断标识，保留阶段、时间与规范错误 |

调用只读收集器；不能为了补状态自动 reconcile、联网、自愈、下载订阅或抓取真实流量。每节标注实际取得的数据与命令退出/缺失/超时，坏配置、不可用命令或一节失败不能使其余报告消失。报告结束标记和截断标记可检查。

## DIAG-003：资源与隐私

所有外部命令共享 25 秒预算；每条命令仍有自己的较短上限。单流 32 KiB、每节 48 KiB、整份报告 512 KiB；配置读取 4 MiB，最多六个日志，各尾部 32 KiB/120 行。拒绝 FIFO、链接或无界读，不为大文件建立完整行索引。超限明确截断/跳过，不为追求“完整”耗尽内存。

不导出订阅 URL、query/token、密码/密钥/UUID、SSID/BSSID、设备标识、原始 UID/应用清单、节点显示名或用户流量目标。配置结构使用报告内一致的匿名别名保留顺序与引用关系，凭据字段仅保留是否设置。错误和日志同样脱敏；URL、转义和多种 header 形式应有合成 canary 验证。核心数字版本和公共错误类型应保留，避免脱敏到没有诊断价值。

报告路径/大小是元数据，不能把整份报告或原始出错 stderr塞进普通 UI 输出。WebUI 导出成功仅在能力协商、成功退出和完整 schema/command/path/bytes 校验后显示；失败清除旧成功提示，保留安全错误代码。MCP 自动资源只读缓存状态；`magicnet_support_bundle` 是显式完整脱敏收集入口，不自动替用户执行恢复。

## 验收 DIAG-A01–A06

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| DIAG-A01 | WebUI 单击/快速双击、CLI human/machine、旧版能力不支持、未知尾参 | 一次操作仅生成一个完整文件；能力不足不执行写；单 JSON、非零错误与 UI 提示准确 |
| DIAG-A02 | 无网络、坏配置、命令缺失/超时/大量输出、系统资料权限不足 | 可用节仍保留，缺失/退出/超时/截断明确，总预算和字节上限有效 |
| DIAG-A03 | 两次并发导出、临时文件冲突、写入失败/中断、旧报告存在 | 无半文件、旧报告不被失败覆盖；最后成功完成报告生效，临时文件有归属且清理 |
| DIAG-A04 | 注入 URL/凭据/header/节点名/SSID/boot token/UID/日志 canary | 输出中均无 canary，结构/计数/类型/引用可追踪，核心版本与规范错误仍有用 |
| DIAG-A05 | 导出前后比较 canonical、配置、订阅与网络调用计数 | 除指定诊断文件外不修改运行意图/观测；公网请求、自愈和刷新计数不增加 |
| DIAG-A06 | 固定发行 CLI 与合成配置重复运行并测耗时/CPU/RSS | 记录样本、文件大小、核心子进程成本与测量范围；单进程峰值不是常驻或进程树并发总量 |
