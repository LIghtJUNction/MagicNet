# 订阅导入、合并与恢复合同

本质：订阅列表中的每个来源都要得到完整的候选节点；只有整批候选校验通过，才能一起替换正在使用的配置。来源个数、节点个数和网络是否可用是三个不同结果。

本文件是 runtime 配方 0.1.1 的必读部分，覆盖 URL/本地来源、转换、缓存、合并、激活、恢复、周期刷新和订阅状态。保留本包其他 Android 网络要求。实现语言、进程组织和私有临时文件布局自由；下文列出的 CLI、既有配置导入、公开状态及行为边界必须保持。新增公共 JSON 的字段、能力名和披露范围以控制面 `SUBSCRIPTION_INTERFACE.md` 为准，不从本文另造一套接口。

## 2. SUB-001：来源入口与边界（保留）

- 远程模式接收一至五个不同的 HTTPS 订阅 URL，每行一个，忽略空白行；去重后超过五个必须拒绝整份候选，不能悄悄截取前五个。空文本不是“清空”的别名。
- 人类 CLI 保留 `setup <url>`、`sub set sing-box <url>`、`sub set-file sing-box <base64-lines>`、`sub apply-file sing-box <base64-lines>`、`sub update sing-box|all`、`sub update-all`、`sub clear`。`singbox` 保留为既有目标别名。`set` 是替换为一个来源，不是向列表追加；列表写入口会验证并应用，不是只写文件。
- `sub get` 是旧式首个 URL 读取，不可让多源客户端用它代表完整列表。完整私密读取走能力协商后的 `sub.inspect`，旧文本兼容层才使用 `sub list`。
- WebUI URL 文本通过私有 payload 入口传入，不拼进 shell 命令。payload 的原始 UTF-8 字节、换行、query 和长字段在分块上传后必须完整保留。
- 本地模式接收一个 UTF-8 订阅文档，最大 8 MiB；拒绝空白内容、NUL、无效 UTF-8、超过上限和非受控路径。缺少末尾换行可补齐。它与 URL 列表互斥，切换成功才移除旧模式的活动来源；失败保留旧模式。不得将本地文件上传第三方在线转换服务。
- 兼容导入已有 `.config/sing-box/subscription.url`、`subscription.local`、`subscription.user-agent`、`subscription-filter.list`。这些是用户配置兼容边界；新实现不必复制所有内部暂存路径。发现损坏旧文件时报告并保留，不把“读失败”当作空列表。

## 3. SUB-002：所有入口使用同一来源身份（重建修正）

新规范对 WebUI、CLI、MCP、配置迁移、下载、缓存和用量读取一致：

1. 接受 LF、CRLF、CR 行分隔；去掉每行首尾空白，忽略空行。每个非空行必须是一整个 URL，不接受行内注释或逗号/空格分隔的多个 URL。
2. 仅允许 HTTPS。scheme 和 ASCII 主机名转小写；默认端口 `443` 省略；没有路径时补 `/`。非 ASCII 主机必须先按相同的、明确实现的域名序列化规则转成 ASCII，再执行主机合法性检查；不能让不同入口分别猜测。
3. fragment 从网络来源中移除，界面告知它不参与订阅请求。不得用任意 `#` 截断包含在 percent 编码中的内容；`%23` 仍是原 URL 的数据。path/query 中已有 percent 编码不解码、不改变大小写；query 参数不重排，重复参数和空值保留。非 ASCII path/query 字符统一按 UTF-8 percent 编码；不得把 `+` 当空格，或把 `%2F` 当路径分隔符。
4. 用规范化后的完整 URL 精确去重，保留首次出现顺序；同一主机的不同 path/query 是不同来源。后续拉取不能再用另一套清洗规则改变已确定的身份。
5. 来源顺序是显示和本次进度的顺序，不是缓存键。缓存和来源用量以规范化完整 URL 的强身份绑定，不得用行号或 hostname 代替。迁移旧缓存时只在旧 URL 与新规范化 URL 的映射可证明且无歧义时重建身份；否则重新获取，不串用旧数据。

公开合成例子：输入 `HTTPS://A.example.invalid:443#one`、`https://a.example.invalid/#two`、`https://a.example.invalid/sub?x=1&x=2`、`https://a.example.invalid/sub?x=2&x=1`，得到三个来源：`https://a.example.invalid/` 及两个保留参数顺序的 `/sub?...`。`?token=a%23b` 不等价于 `?token=a`。上述 `.invalid` 样本只用于离线解析或受控测试，不对公网请求。

旧实现差异必须保留在迁移说明：WebUI 的 URL 序列化保留 fragment，Rust 按 trim 后原文本去重，shell 在计算 SHA-256 前删除原始 `#` 后的内容。因此不能拿旧三者某一路的数量解释另一路，也不能把本条称为已验证的旧行为。

## 4. SUB-003：每个下载目标都要验证（保留；整批约束为重建要求）

- 拒绝非 HTTPS、userinfo、空主机、内嵌空白/控制字符、非法端口和私有/特殊用途地址。主机解析得到的每一个 IPv4/IPv6 地址均需通过公网地址策略；混合“一个公网、一个私网”也拒绝。禁止 loopback、link-local、metadata、multicast、CGNAT、文档保留网段及其他非公开目标。
- 每一跳重定向都重新做 scheme、主机、解析地址与 TLS 检查并绑定已验证地址，不能先解析检查一次、连接时再任由 DNS 换地址。保留证书校验，失败不转成 insecure 重试，不降级 HTTP。
- 最多五次允许的重定向；只有 2xx 且非空响应可用。默认连接预算 10 秒、每来源总预算 45 秒，总预算包含 DNS、跳转、退避和响应体；可配置值有上限，连接最多 30 秒、总预算最多 120 秒。DNS 预算不超过剩余总预算且默认最多 10 秒。
- 瞬时网络失败及 HTTP 408/429/500/502/503/504 最多重试两次，退避 1 秒、2 秒仍计入同一总预算。证书/策略/格式错误不得靠无限重试掩盖。
- 每来源解压后的响应体最多 8 MiB；流式读取同样有界，不能仅相信 Content-Length。源码通过 `curl --compressed` 将输出写入 FIFO，再读取至多 8 MiB+1 字节并按实际长度拒绝超限，因此限制针对 curl 解码后的输出；本轮没有运行真实压缩响应的网络验收。响应头处理最多 64 KiB；不保存 Cookie、Authorization 或原始头。旧源码证明的是每来源预算，不能据此声称五源共享一个 45 秒整批预算；五源串行、并行均可，整批可观察进度、可恢复取消与明确总截止边界是本轮重建要求，具体批次期限须在实现交付中声明并验收。
- 下载不能被用户 curl 配置、环境代理或 loader 变量改成另一目标/代理通路。旧 `MAGICNET_SUB_PROXY` 绕过地址验证的路径不允许悄悄启用。下载器缺失、无法可靠验证目标或无法限制资源时明确失败。

## 5. SUB-004：整批来源完整性与缓存降级（保留并补足诊断）

- 每个规范化来源都必须贡献一份有效取得的输入，取得方式只能是本次 fresh 或已核实同一 URL 身份的 cached。不得让 A 下载成功掩盖 B 失败后只导入 A；只要有来源无法取得，整批保留旧有效代。
- 缓存使用 SHA-256 或至少同等强度的完整 URL 身份，并核对来源证明；不同 URL、相同主机、相同行号、旧顺序、旧无证明缓存不可互用。无法计算强身份时允许 fresh 下载，禁止使用弱散列猜缓存。
- fresh 获取失败时，可使用同一来源已验证的旧缓存，并明确显示 cached、原更新时间；明确“要求 fresh”的调用则不允许降级。缓存通过不能显示“本次成功从网络拉取”。
- 每一缓存来源仍经过本次格式、完整性、节点和候选配置校验。不能因为数据在缓存里就跳过验证，也不能在解析新下载内容失败后悄悄改用旧缓存掩盖格式错误。
- 缓存内容、身份与用量元数据不得跨代串配。元数据发布失败应变为 unknown，不能把旧配额贴到新响应上。提交后可清理不再使用的来源缓存；失败或无法读清理清单时不可误删活动缓存。
- 本次 A fresh、B cached 且两源完整可提交；A fresh、B 失败无匹配缓存必须回滚；A fresh、B 来自 C 的缓存必须回滚。不同情形均在同一批次结果中可区分。

## 6. SUB-005：格式和字段语义完整性（保留；encryption 按引擎合同补齐）

- 输入覆盖 sing-box JSON、Clash/Mihomo YAML、文本分享链接及 base64 包装；远程与本地走相同语义检查。原生支持的协议族为 SS、SOCKS、VMess、VLESS、Trojan、Hysteria2、AnyTLS、TUIC，不把名称匹配当作所有扩展均已支持。
- 解析必须保留影响连接的 server、port、认证、TLS/SNI、ALPN、Reality、transport 及其参数。VMess WebSocket 的 server、HTTP Host、SNI、path 是四个独立字段；SOCKS 有认证时 username/password 必须同时有效；端口为 1–65535 的整数。
- VLESS `encryption` 不得静默删除或改成 `none`。其长密钥、模式、编解码和核心配置字段服从 engine 的 VLESS encryption 合同，不能套用节点名/UA 的短长度限制。旧原生 query allowlist 不接受该字段，不能把旧原生 VLESS 统称为完整 encryption 支持。
- YAML 的 anchors、alias、嵌套数组、flow style、块标量、转义、BOM、CRLF、复杂 TLS/transport 等需要完整语义支持。只会取几个标量的原生解析器不得吞掉不认识的选项继续成功。
- 转换器可使用已审核的本地第三方实现，必须逐个原始来源转换；不能只转换一个汇总的 `links.txt`，因为它遗漏 JSON/YAML 来源。转换器的输入、输出、执行时间有界；参考行为默认 12 秒，允许配置范围 1–60 秒。超时/缺失/非零退出必须可诊断。
- 完整转换失败后，只有所有来源、所有候选节点均被原生路径完整表达时才允许回退。任何依赖未实现字段的来源存在，都拒绝整批并保留旧代。支持的节点与不支持的节点混在同一文档中，也不能只取支持部分后显示成功。
- 下载成功只证明取得字节；base64 可解码只证明编码；转换器退出 0 仍需校验输出类型、节点及语义；核心 check 通过不证明远端能连接。

## 7. SUB-006：先证明每源完整，再计算合并数量（重建修正）

逐源记录原始候选、成功转换、明确过滤、完全重复和拒绝原因，最后汇总有效结果。重复项与用户主动过滤不属于转换丢失；不认识的协议/字段、只输出 direct 的来源或转换器漏掉一个真实节点不能被别的来源更多节点补偿。

**禁止把“跨来源去重后的节点数量”与“去重前原生提取的条数”直接比较，作为转换完整性的证明。** 数量相等也不能证明字段正确。JSON/YAML/分享链接混合时，某个原生路径数到零不代表该来源不需要检查。

转换器不能提供逐项 provenance 时，重建实现仍需通过逐源验证、受控字段对照和真实转换器回归证明该来源完整；拿另一源的节点补足总数不合格。不能为了让多源成功而删除完整性检查。

## 8. SUB-007：同名节点、真正重复与稳定选择（重建修正）

- 显示名不是节点唯一身份。两个节点同名但 server、port、协议、认证、TLS 或 transport 任一语义字段不同，必须保留两者；不能“第一个 tag 胜出”而静默舍弃第二个。
- 完全相同的连接语义可以合并，但需保留全部来源归属。合并必须忽略显示名及 JSON 对象键序这些非连接语义；不能忽略凭据、TLS 检验开关、Reality/encryption 或 transport 选项。无法确认等价时保留为两个节点。
- 非冲突、非保留名的既有 tag 尽量保持。冲突或碰到系统保留 selector 时生成安全、确定且稳定的内部 tag，显示仍可保留原名并显示来源区分；同一来源内容不变、仅重排来源或刷新时，节点身份与手选结果不得漂移。
- 稳定身份不能仅由“第几个订阅、第几个节点”决定；新增第三源不能改写无关已选节点的身份。具体编码算法由实现选择，但同样的规范化来源和连接语义必须得到同样身份，碰撞须检测并显式处理，不能覆盖。
- 节点重命名后，原文中允许的 detour/节点引用必须按同一来源的已确认身份一起重写；存在歧义或缺失时拒绝候选，不能误指向另一来源的同名节点。重命名只改变标识，不改变连接语义或绕过受控引用校验。
- `proxy`、`proxy-auto`、`direct`、`block`、服务 selector 以及 `magicnet-chain-*` 等系统 tag 不得被订阅占用；源文档带同名节点应安全改名或明确拒绝整批，不能替换受控路由。
- 输出节点顺序为来源首次出现顺序、每源原始节点顺序；若合并完全重复节点，保留首次出现位置并累积来源。不能把文件名 `node-10` 的字典序偶然变成优先于 `node-2` 的产品规则。
- 刷新后仍存在的节点继续承载原手动选择；完全删除所选节点时按公开 selector 回退规则处理并告知，不能把同名但不同端点的节点当作原选择回放。

## 9. SUB-008：UA、过滤与空结果（保留）

- UA 可读取、设置、清除。UTF-8 去首尾空白后为 1–256 字节，不含控制字符；空值应使用 clear，不伪装成合法 set。自定义值对本次各源及重定向保持一致；清除后回到默认下载器行为。
- 用户过滤词每行一个，去首尾空白，空行忽略；最多 32 个不同词，每个最多 64 UTF-8 字节，无控制字符；不区分大小写去重，保留首次拼写。匹配是文字子串，不是正则，不把用户词解释成命令或模式。
- 自动过滤明确的套餐/用量/到期提示节点，保留现有通知词：剩余流量、到期、过期、套餐、官网、订阅、Traffic/traffic、Expire/expire、Expired/expired、Subscription/subscription、官方网站、更新订阅。用户过滤词和这些已知通知项需分别计数，不能混作协议解析失败。
- 过滤改变不能破坏转换前完整性判定。原先有效的节点被用户明确过滤可以计入 filtered；不支持字段被悄悄丢弃不可以计入 filtered。
- 整批最后没有任何可用代理节点时拒绝应用并保留旧代；首次零节点引导配置保持 fail-closed 的 block，不默默改全直连。某源全部被用户过滤但其他源有节点时可提交，其来源仍可见且节点数为 0，显示明确过滤原因。

## 10. SUB-009：每来源用量与有效期（保留并统一身份）

- 只从最终完整 2xx 响应的 `Subscription-Userinfo` 提取 `upload`、`download`、`total`、`expire`；字段名大小写不敏感。中间 103/3xx 头、未结束的头、超过头预算的数据均不能作为最终配额。
- 原始 HTTP 头中的数值 token 必须是 1–16 位 ASCII 十进制数字，且不超过 `9007199254740991`；负数、指数、NaN、重复字段或越界值对应字段为 null，其余独立有效字段可以保留。它们在头里本来就是文本，不能与后续 JSON 类型混淆：私密 inspect 读取 JSON 用量时只接受非负整数数值，拒绝把字符串 `"123"` 当作数值。`expire=0` 为未知；最终机器接口的 `expire_epoch`、`updated_epoch` 还必须为正整数且不超过 `253402300799`，以控制面合同为准。
- 按 SUB-002 的同一来源身份关联，不按位置。重排 A/B 不交换配额；没有用量头的来源仍保留一行、未知用量字段为 null，不减少已配置来源数量。完全没有可信元数据时 state=unknown；旧下载器在完整 2xx 但无用量头时可以产出 state=fresh 且全部配额字段为 null，不能据 fresh 编造配额。缓存配额标 cached 且保留原更新时间；fresh 不代表全部配额字段都有值。
- 未提交的工作代、事务恢复中或观察到代号改变时，不能把候选配额冒充活动配额。私密 inspect 读到不一致快照应给可重试的结构化错误，不能拼接两代。
- 公共 status、canonical 状态和自动支持包只公开必要计数/token，不公开 URL、hostname、来源 hash、节点名、凭据或原始响应。明确私密读取可返回授权 UI 所需的配置/用量；该能力不自动开放给 MCP 资源。

## 11. SUB-010：候选配置与用户策略保留（保留）

订阅来源是候选节点输入，不是授权供应商替换整个 Android 网络配置。合并时保持模块控制的入站、DNS、路由、应用策略、用户覆盖、代理链、Tailscale 和服务 selector 边界；各项的优先级遵循 policy 与 control 合同。用户覆盖不能因更新来源而永久丢失，失效引用必须显式验证。

候选是完整结构化 JSON 对象和完整节点数组，不能用正则剪接 JSON。先校验语法、节点字段、引用、系统保留名和有界资源，再用实际目标核心完成 `check`。核心缺失、不可执行或拒绝时，不能因为 JSON 语法合法而进入激活。复杂配置尚未校验前，不覆盖唯一的有效配置。

## 12. SUB-011：激活与结果层次（保留）

整个更新至少有 prepare、fetch、convert、validate、activate、commit、complete 这些可观察阶段，阶段变化主动发布；耗时操作退出 UI 后仍可读取。一个 generation 贯穿候选、状态、恢复和结果。

- 原先核心停止：完成候选验证和来源提交后仍保持停止；不能为导入订阅擅自启动用户未运行的核心。结果是“已保存，待启动”，不是“网络已可用”。
- 原先核心运行：只重启可证明归本模块拥有的核心，验证新代已加载与需要的运行资源；失败恢复旧有效配置和原运行意图。PID 活着但加载代不匹配不是成功。
- 保存成功、配置 check 成功、核心/API 就绪、节点可连接及真实应用流量分别报告。公网探测失败不能伪造整个业务通过；也不能把已提交的配置谎称为完全没有提交。
- 提交后 selector 回放失败保留现有成功退出码 0，并向 stderr 单独发出“订阅已提交、选择恢复有警告”；本轮新增 batch 保持 `outcome=committed`、`error_code=none`、`warning_code=selector_replay_failed`，按控制面合同发布。允许只重试选择恢复，不能谎报订阅整体回滚或再次盲目提交相同源。
- 未产生有效配置变化时允许避免重启，但仍正确更新本次取得方式、用量、计数和来源状态；不能只凭节点数相同判定配置相同。

## 13. SUB-012：整批事务与中断恢复（保留）

事务范围覆盖活动配置、已提交 URL/本地模式、工作代、来源归属、已保存选择与用量代。公共读取不能在混合代上宣布成功；多个 rename 不是对所有读者同时原子可见，需要机器快照/代号保护。

写前必须有独立且已经校验的恢复基线，不能把已损坏活动文件复制后称为 last-known-good。记录原运行状态和足够的持久恢复证据；各阶段失败、HUP/INT/TERM、进程崩溃后均能安全重试恢复。恢复证据不完整、权限错误或归属不明时保留 journal 并显示 recovery_pending，不猜成已恢复。

配置替换、核心验证、工作代切换、来源提交后分别注入故障：要么得到同一新代的完整成功，要么恢复完整旧代，或明确保留可继续恢复的未完成状态。恢复完成之前不能发布新 success_epoch。原 URL→本地→URL 的双向切换同样受此规则保护。

恢复时如果配置字节、运行代指纹与核心就绪都已匹配，允许避免不必要重启，但必须补齐可能中断的 DNS/透明策略；只因 PID 仍存在而跳过恢复不合格。只能回收本次拥有的临时资源，不删除其他任务文件或无关进程。

## 14. SUB-013：并发、取消与所有权（保留）

手动应用、定时刷新、clear、生命周期恢复共用可证明身份的单一订阅写 owner，并与配置生命周期串行。活跃任务返回 busy/可重试结果；调用端超时、WebView 关闭或按钮重新点击不得偷走仍运行的 owner。

owner 至少绑定 PID 的启动身份及任务身份，不能只靠 PID 存在。重用 PID、空 owner 发布窗口、损坏 owner、不可读 proc 必须分别处理；未知状态不能强杀或强删锁。安全确认旧任务已死才回收，并先恢复 pending 事务。

取消是请求设备侧停止并恢复，不能仅停止 UI 等待。取消/超时后仍可能已提交；必须读回 generation 的最终结果再决定重试。完成者仅释放自己的 owner，不能删除后来接手任务的锁。

## 15. SUB-014：刷新计划与清空（保留）

- 计划值只允许 `off|12|24|48|72` 小时，默认 off；同一配置最多一个刷新 owner。重复启用不产生第二个循环；关闭/卸载有界停止自有任务；未知归属报告不确定。
- 计划刷新使用与手动更新相同的全来源、缓存、转换、事务与状态规则，不触发上游业务分类数据更新。间隔从受控计划计算，不靠 UI 仍打开。配置计划值与当前是否有有效 owner 分开显示。
- `sub clear` 移除 URL 与本地来源意图，保留当前已验证配置和正在工作的网络。它不能绕过活跃 updater 或 pending 恢复，不是清空缓存、停核或恢复出厂的别名。清空后状态必须显示零来源，而不是把上一次成功数量当作当前数量。

## 16. SUB-015：可定位多源失败的状态（重建修正）

控制面 `subscription_batch_v1` 为本轮批次进度与逐源结果的权威合同。至少能区分提交的候选条数、规范化后不同来源数、旧的已配置来源数、当前 generation/阶段、每源 fresh/cached/failed/not_attempted、转换结果和最终 committed/rolled_back/recovery_pending。

失败的三源候选不能只显示旧配置仍为一源，就让维护者猜用户是否只输入了一条；旧的 `source.configured_count` 仍表示已提交配置，新增批次字段不改写旧字段语义。逐源索引对应本次 generation 的规范化候选顺序；公开结果不需要来源 URL/hostname/hash。UI 只有保有同一 generation 的冻结候选时，才能在私密页面把索引关联到具体来源；重开、换草稿或没有该候选时只能显示匿名“来源 1/2…”。现有私密 inspect 返回当前已提交来源，不能拿它或当前草稿映射失败候选；本轮没有新增 inspect 候选详情能力，更不能直接公开恢复 journal。

获取失败、TLS/DNS/超时、响应过大、转换器不可用、语义不完整、全部过滤、核心校验失败、激活失败及恢复未完成应可区分为规范 token，不能公开原始错误文本。不能把多个来源的 converter_format 简化成最后一个来源的格式；混合输入应报告 mixed 或按来源报告。

原生提取后的计数与构建显式捕获每个节点的解析失败，不依赖调用者或 shell 对 set -e 的不同继承行为。一个不支持的 SNI/TLS 字段与一个有效节点混合时，各 shell 均保留整个候选失败及旧配置，已知的语义不完整不得被提前退出误报为计数设施错误。

保持现有 `schema=1`、capabilities、canonical token 约束。新客户端先协商，旧版本缺少批次能力时明确“缺少逐源结果”，不把缺字段当作 0 或 success。

## 17. 已复现的旧聚合缺陷与未决项

在固定源码的真实原生提取、有效计数、合并和 selector 生成函数上，使用合成的转换器输出做离线实验：A、B 各一个 Trojan gRPC 节点，tag 都为 `shared-name`，server 分别为 `a.example.invalid` 与 `b.example.invalid`；协议、port、凭据、transport 其余字段合法。未运行真实转换器，不联网、不修改设备。

| 输入 | 原生提取数量 | 原生完整性 | 聚合返回 | 观察 |
| --- | --- | --- | --- | --- |
| 仅 A | 1 | 非完整，gRPC 不能原生回退 | 0 | 转换后导入 1 |
| 仅 B | 1 | 非完整 | 0 | 转换后导入 1 |
| A+B、同名不同端点 | 2 | 非完整 | 1 | 合并去重数量 1 小于原始 2，被认作转换不完整 |
| A+B，仅把 B tag 改为 `unique-b` | 2 | 非完整 | 0 | 转换后导入 2 |

这证明旧聚合层存在一个与“单源可用、多源失败”相容的缺陷。它不能证明 #426 的真实订阅有相同 tag、真实转换器能正确转换其全部字段，或报告设备一定走了此分支。原生简单来源可能走回退而表现为少节点，和复杂来源整批拒绝不同；重建不得保留任一种静默丢节点行为。

尚待新实现与真实设备验证：真实转换器的混合格式与 encryption 支持、五源完整数据流、长 URL/长协议字段跨桥接无损、OEM 网络和重启恢复、真实节点连接。Android/网络未验证项不得被本地合成实验消除。
