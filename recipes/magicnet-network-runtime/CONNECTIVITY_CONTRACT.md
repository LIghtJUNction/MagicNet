# 低频联网探测与恢复

本合同定义既有监督循环中的主动探测、恢复与核心退出后的自有资源清理。进程存活、配置有效、本机 API 可用与外网请求成功分别是不同证据。主目标为 `https://www.google.com/generate_204`，辅助目标为 `https://cp.cloudflare.com/generate_204`。当前所选代理通过核心严格接口直接验证两个 HTTPS 204 目标，另行观测本机 mixed 入口的数据面结果；两者不得互相代替。TLS 校验通过且实际收到 204 才能记对应目标成功，旧延迟 API 的成功不构成该证据。结果也不能代替某个 Android 应用 UID、热点客户端或全部 TUN/eBPF 数据面的实际流量验收。

## CON-001：频率、预算与状态

正常每 300 秒探测一次。连续失败采用 60、120、240、480、960、1800 秒的指数退避，此后上限保持 1800 秒；成功后恢复 300 秒。已有监督循环每 60 秒唤醒一个短命令，未到期立即返回，不能随页面刷新增加网络请求。截止时间采用包含休眠的单调时钟，开机身份与截止时间原子保存；同次开机的 worker 重启、重复调用和系统时间前后跳不能重置退避。重启设备后旧单调时间失效，状态先为 stale/pending，不伪装为新成功。

当前所选代理与候选代理使用核心 `expected_status=204` 严格 HTTPS GET，禁止重定向并检查能力标记、结果和真实 HTTP 状态；每个请求有明确截止时间，不能因旧核心回退到 HEAD 而宣告成功。独立 mixed 与直连差异探测沿用有界 curl：连接上限 4 秒、请求上限 8 秒、父进程预算 9 秒、输出上限 1 KiB，不下载正文、不跟随重定向、无内部重试。网络请求不能使用用户 curl 配置或失控的代理环境。所有子请求和候选检查计入整次动作期限，测量、通知和日志有界；复用现有监督生命周期，不新增常驻 Rust 服务。

`.state/machines/connectivity.state` 是唯一公共规范状态，schema=1、有界 token、原子替换。producer 保存下一次到期、失败次数、恢复级别和订阅冷却；普通 reconcile 不覆盖其预算。开机身份不进入机器 JSON 或支持包。读取、health、MCP 资源及诊断导出都不发起新公网探测、不更新状态、不执行恢复。

旧 mixed 探测缓存不能在升级后被重新解释为当前所选代理的严格成功。canonical 使用内部 probe_path 标记探测语义；缺少或不符合新严格路径的旧状态，即使仍在 online 新鲜期，也应读作 unknown 并由 producer 安排立即到期的新检查。迁移保留已有动作冷却、订阅刷新间隔、TUN 尝试次数和其他恢复预算；普通读取只呈现降级后的事实，不借迁移执行探测或重置预算。

## CON-002：差异探测与警告

每次真实检查验证当前所选代理的 Google 与 Cloudflare 两个 HTTPS 204 目标，同时独立记录经过 mixed 入口的实际请求结果。mixed 的路由规则可能选择其他代理，因此 mixed 成功不能覆盖当前所选代理失败；所选代理成功也不能覆盖 mixed 数据面故障。两个严格目标均失败后，才以直连 `https://www.baidu.com/` 区分上游故障和整体断网。辅助成功不能代替 Google 成功；记录主目标与综合原因，区分真实 HTTP 错误、传输失败、超时、能力不可用、缺默认路由和目标特定失败。网络、路由或执行器证据缺失须如实显示 unknown/不可用，不能靠假定填成功。常规检查、最多三个候选的检查与切换复验分别有界，不能循环扫描全部节点。

WebUI 概览、诊断页和 health 显示明确 ⚠️，包括失败、重试时间和最近恢复动作。故障/恢复转换才通知，不能每次读取或每次失败重复刷通知。状态至少有 unknown、pending、online、degraded、offline、paused、stale；pending 的再次检查保留上次失败警告。恢复动作成功仅表示动作执行结果，只有后续主目标成功才能显示 online。

## CON-003：有条件自愈

至少连续两次失败、当前所选代理的两个严格目标均失败、直连成功且没有确认缺少默认路由，才允许进入自动恢复。仅 Google 失败、严格能力缺失或整体断网继续探测和警告，不据此连续切换或重启。恢复动作最少间隔 300 秒；已有同组真实代理的有界候选恢复按 CON-007 执行，其余自有路由/DNS修复、事务性订阅刷新和受控核心重启继续遵守既有阶段与证据条件。自动订阅刷新最少间隔 3600 秒，整次自动动作预算 300 秒；仍遵守既有来源下载安全、候选校验、完整批次、原子替换和失败恢复。

恢复复用生命周期/配置锁。锁忙有界返回 deferred/busy，不能重启正在被其他操作管理的核心；得到锁后重新确认模块启用、当前核心活着且归属明确。用户停止、停用、卸载或进程归属未知时暂停，不尝试启动来掩盖失败。保留 tun|ebpf、用户配置和停止意图；仅 CON-007 允许在已验证候选之间改变相关组的选择，其他组及手动新选择保持。不得调用需要用户确认的 Android network-access 策略写入。

订阅激活或重启可能停止当前监督父循环。正在执行的恢复 worker 必须完成并发布回执；只终止有归属证据的父循环，不误杀整个进程组。恢复后的循环恰好一份，不继承配置/探测锁或一次性命令预算；中断和失败继续保留有界退避及恢复证据。

显式 service stop/restart 优先于自动恢复：停止 producer，并按完整 argv 与进程启动身份取消本模块 worker。给现有订阅 TERM/回滚流程最多15秒，持有生命周期锁直到子组结束，取消场景争锁预算最多20秒；无法完成仍明确 busy/error。取消后记录 paused/stop_requested，不自动重建监控、重放选择或启动核心；不能只杀父控制器而留下继续持锁/重启的子进程。

## CON-004：实际可用的 HTTPS 执行器

正式模块必须提供受管 `bin/curl`，不能假定 Android 系统或另一个 root 模块已提供 curl。生产 ARM64 与模拟器 x86_64 使用同一固定源码、TLS/压缩依赖及 CA 构建流程；版本、源码摘要、ABI、执行权限和 TLS 信任根随组件校验。正式下载和探测使用模块可信绝对路径，不以测试临时注入的工具代替生产依赖证据。

禁用用户 curl 配置，清理可改变代理、CA、TLS 后端和 TLS 密钥日志行为的继承环境；显式代理与证书验证继续生效。工具缺失、不可执行或输出无效时保留 `probe_unavailable`/`probe_invalid`，不能将本机执行器故障归为上游网络失败，更不能满足自动恢复的网络证据条件。

实际 Android 验收应在无系统 curl 的环境中执行安装后的模块 curl，核对版本、HTTPS/TLS/gzip能力及嵌入CA的实际内容摘要，完成证书正确/错误对照。至多一次显式产品 tick 验证实际请求或既有有效探测结果；保持去重、到期时间和原预算，不能改状态强迫重复请求。Google 204、网络失败和未执行分别记录；导出本身仍不联网。

## CON-005：TUN 自动路由恢复

FIB 先按 route_address 扣除 route_exclude_address，忽略目的范围与必要范围完全不相交的路由。此类条件路由不影响完整覆盖，也不掩盖必要范围的明确缺失。相交路由中的非零 `tos` / `dsfield` 只覆盖匹配该流量类别的报文，普通流量覆盖保持未知。非零、命名或无法解析的条件，以及缺少条件值的输出，使用既有 `route-selectors-unobserved` 保持 unknown；明确数值零保留默认匹配。健康、机器接口和 watchdog 共享该观察，机器无其他已知缺失时 readiness=null，watchdog 清除连续缺失且不执行恢复，已有联网观测与恢复预算保留。

复用同一 watchdog，每 60 秒独立观测当前 TUN 的必要 RPDB/FIB 证据，不受 Google 探测退避影响。只有显式 tun、auto_route=true、核心归属明确且实际启动满 90 秒，同一核心启动身份的连续两次完整观测均确认必要资源缺失，才允许恢复；任一观测未知、事务未完成、模块停用或用户停止均不能触发。present/unknown 或核心换代清除连续缺失计数，不能清除同次开机的恢复预算；已有预算损坏保持不可恢复，不按零次重新授权。

有效 TUN 路由已覆盖必要范围，但仍有未能由更具体 TUN 路由排除的竞争前缀时，该路由证据为 unknown，不计入连续缺失或触发重启。即使另一必要项已知缺失使 readiness=false，只要本轮仍有未知证据，就不满足完整观测的恢复条件。

取得现有配置/生命周期锁后重新核对上述条件，调用当前核心的标准重启流程，由原所有者重建规则；不猜固定优先级、不直接重放或清空系统路由。所有联网恢复动作共享至少 300 秒冷却，TUN 重启依次退避 300/600/1200 秒，同次开机最多尝试 3 次；先原子预留次数再执行，CLI/worker 重跑与恢复成功不重置预算。耗尽后继续观察和告警，只有新开机重置。

在同一 connectivity.state 内持久化有界 tun_* 字段，通过只读 `tun_auto_route` 对象单独公开状态、时间、连续缺失数、尝试数和动作结果。所选代理、mixed 数据面和 TUN 证据分别记录，重启动作成功不等于任一路径或应用流量恢复。普通读取、health 和导出均不执行恢复；公共数据不包含 PID、boot 身份或原始规则。

## CON-006：核心退出后撤销自有网络捕获

核心已经退出时，留在内核中的 DNS 转发或热点路由仍可能把请求送往无人接收的端口或接口。既有 watchdog 的 tick 在确认核心 stopped 后，尝试取得配置/生命周期锁，并在锁内重新确认核心仍停止、模块未停用且当前 worker 未被取消；条件成立才调用现有停止后清理。正常停止已执行相同清理，重复调用必须幂等。手动 check 自身只观测；核心停止时未完成的观测请求不得阻止后续后台 tick 按上述条件清理。无需通过推测退出原因区分手动停止与崩溃，也不得因这次清理自动启动核心。

清理仅撤销现有 ownership 证据覆盖的 DNS 捕获、DNS guard、自有路由及热点 offload 设置；不 flush 系统规则、不修改订阅/模式/节点选择。控制面配置锁被占用时非阻塞跳过；同时按 LIFE-010 取得直接 Shell/开机入口共用的配置锁，等待最多 2 秒，整个清理调用最多 45 秒。锁内发现活跃核心或身份未知、停用或停止请求时不清理。清理失败保留未完成的归属与恢复证据，后续现有 tick 再尝试，不增加监督进程或重启预算。

此路径不进行公网探测，也不把清理成功写成联网成功。connectivity 继续使用既有 paused/core_stopped 语义；tick 的清理失败返回 connectivity.cleanup_failed，实际资源错误沿用既有生命周期与 transparent 对账。普通 status、health、MCP 读取和诊断导出保持只读，不因读取触发此清理。

## CON-007：当前所选代理与有界候选恢复

故障判断必须针对 proxy 组当前实际选中的出站，避免 network-test 等路由组掩盖日常代理失效。严格结果须同时满足 `strict_probe=true`、`expected_status=204`、`ok=true` 和 `http_status=204`；0 ms 延迟有效。缺少标记、畸形结果、能力不支持或请求未完成均不能进入成功或“候选已验证”状态。所选代理与 mixed 数据面在同一 canonical 域分别保存，只读界面与诊断显示各自结果、原因和时间。

自动候选只能来自当前选择器已有成员中的真实代理，排除当前项、direct/block、selector/urltest 以及不属于该组的出站。每次最多尝试三个候选，不下载新节点、不创建跨组候选、不递归展开任意组。每个候选必须先通过 Google 和 Cloudflare 两次严格 HTTPS 204 探测，失败继续下一个，全部失败则保持原选择并留下有界证据。动作仍受连续失败条件、300 秒共享冷却和整次截止时间约束。

选择变更在现有配置锁内重查组成员、当前运行值与原保存值。先通过 checked 持久写确认选择可保存，再调用运行时 PUT，随后读回运行时和保存值，并立即进行真实路径复验；保存失败不得触碰运行态。复验成功才将恢复记为成功。任何步骤失败均补偿恢复旧运行值与旧保存值，原先缺省的保存项恢复为缺省。遇到外部新选择时拒绝覆盖并返回 `rollback_conflict`，准确保留未完成差异。跨多个组的变更是可补偿的顺序批次，不声称文件和运行 API 瞬时原子。

恢复动作的成功回执不替代新网络证据。候选通过、PUT 成功或文件已保存都不能单独把状态置为 online；新结果必须关联变更后的真实选择。失败、取消、锁忙及停止意图均保留共享动作冷却、订阅刷新间隔和 TUN 恢复次数，不得为了重试清空预算。等待私有选择变更请求时，读取可显示 pending/selection_changed，但不因读取额外探测。

## CON-008：人工即时检查与状态读取

人类命令 `cli connectivity check` 显式请求一次真实检查，用于长退避期间确认当前网络；切换后的即时复验使用同一受控探测路径。人工 check 只做探测，不执行 repair/refresh/restart，不因人工请求自动切换。检查遵守单 producer、现有互斥、取消和用户停止意图；10 秒节流，忙时返回 `connectivity.check_queued`，节流返回 `connectivity.check_throttled`。实际结果可更新观测与下次探测时间，但不得重置恢复动作冷却、订阅刷新间隔或同次开机的 TUN 恢复次数，也不得凭一次人工检查绕过自动恢复门槛。

`connectivity status`、机器 `connectivity.status`、health、MCP 资源和诊断导出继续只读缓存、零公网请求。`connectivity check` 仅是人类显式入口，不能因同名命令存在而自动开放 `--json` 或 MCP 写操作。概览的“检查网络”打开诊断页，保留既有诊断工具；该跳转或 ping 结果不表示已执行当前所选代理的严格双 HTTPS 204。需要跳过旧缓存时显式运行人类 check；普通刷新仍只读，旧失败等待下一次 tick 的缓存不能冒充本次检查结果。

故障注入前必须确认 qemu/x86_64 模拟器身份，读取并保存 Android Wi-Fi 启用状态，验证 adb 控制链路不依赖即将关闭的接口，再通过 Android Wi-Fi 服务临时关闭 Wi-Fi。在有界等待内连续两个采样周期观察到相同的 netd 清单、RPDB 规则及 eth0 出口：唯一 PHYSICAL 网络只含 eth0，清单中没有 wlan0，Wi-Fi 确为关闭。准备不完整不得注入，RPDB 故障与恢复中的 netd 快照也须保持单 eth0 上联。eth0 的移动数据关闭/开启前再次核对控制链路，保留独立延迟 enable guard；报告的 `restore_method` 必须为 `android_mobile_data_toggle`。恢复后仍要求该上联实际路由、TUN 状态、就绪与同应用 UID TCP 实测通过，不能用链路恢复命令代替流量证据。

固定镜像的 eth0 由模拟蜂窝数据栈管理。关闭前须绑定唯一默认 phone/数据订阅、用户与有效数据启用状态、当前唯一 CONNECTED/WWAN/eth0 连接及 netd 的同一 netId。通过 `cmd phone data disable` 发起断开；命令和观测共用 15 秒截止时间，须取得两个数据启用状态均为 false、连接状态 0、当前精确连接为空和真实接口 DOWN。netd 须完全销毁旧 eth0 网络；仅允许原逐应用 UID 元数据精确迁移到唯一 netId52/UNREACHABLE，其他记录不变，若基线 UNREACHABLE 已有逐应用元数据则拒绝。此后通过 enable 重新建立连接；同一 phone/订阅恢复启用、连接状态 2、唯一 CONNECTED/WWAN/eth0 与 netd 一致，全部原元数据返回，仅 eth0 netId 可变。`cellular_lifecycle` 保存 before/down/after 的规范化 owner、完整 netd 清单及 down flags，由独立门禁核验；数据源只使用明确的当前段，历史日志不计为当前状态。独立 30 秒 enable guard、失败恢复和原 600 秒路由/就绪/TCP 预算保持，不手工写 Android 外部路由。

夹具收尾通过 finally 恢复并在有界等待内核对原 Wi-Fi 启用布尔值；准备、故障或恢复失败均保留失败，缺少恢复证据不得通过。schema=1 报告的 `network_fixture` 保留夹具身份、控制链路检查、两次完整稳定观测和 Wi-Fi 初始/最终状态，由独立门禁核验。本场景覆盖受控模拟蜂窝断续与 RPDB 丢失恢复；Wi-Fi 开关用于隔离模拟器上联，不构成 Wi-Fi 切换恢复证据。

CON-A09 的 schema=1 证据保留前后 netd 网络清单、完整 metadata、eth0 接口索引/FIB 与 RPDB 规则。只在同一 PHYSICAL 网络的权限为已知 NONE、NETWORK 或 SYSTEM 且前后一致，接口/索引/FIB、Allowed UID ranges、Per-app UID ranges 及其他网络均不变时，接受该网络的 netId 变化。采集器与独立报告门禁分别从这些已核验字段派生选择器。

全局规则按该网络的实际权限核对 mark/mask；所有这些规则均要求 `from all`、`iif lo` 和 `lookup eth0`：

| Required permission | 优先级 16000 的 mark/mask | 优先级 23000 的 mark/mask |
| --- | --- | --- |
| NONE | `(0x10000 \| netId) / 0x1ffff` | `netId / 0x1ffff` |
| NETWORK | `(0x50000 \| netId) / 0x5ffff` | 必须不存在 |
| SYSTEM | `(0xd0000 \| netId) / 0xdffff` | 必须不存在 |

逐应用规则不随上述权限改变：每个元数据范围须有 `15000+prio`、`22000+prio` 两条，mark 分别为 `0x10000 | netId`、`netId`，mask 均为 `0x1ffff`，并匹配精确 `uidrange`、`iif lo`、`lookup eth0`。逐项核对完整字段和重复次数；重复或重叠的元数据范围保留各自规则。无法完整解析、缺项、多项、权限变化或无关规则变化均失败。该扩展沿用证据 schema 与生产机器接口。
