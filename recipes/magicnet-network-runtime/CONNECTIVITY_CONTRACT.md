# 低频联网探测与恢复

本合同定义连接后的主动探测。进程存活、配置有效、本机 API 可用与外网请求成功分别是不同证据。主目标为 `https://www.google.com/generate_204`，必须经当前受控 sing-box 的本机 mixed 入口；TLS 校验通过且 HTTP 204 才记为 Google 在线。该结果证明此代理路径，不能代替某个 Android 应用 UID、热点客户端或全部 TUN/eBPF 数据面的实际流量验收。

## CON-001：频率、预算与状态

正常每 300 秒探测一次。连续失败采用 60、120、240、480、960、1800 秒的指数退避，此后上限保持 1800 秒；成功后恢复 300 秒。已有监督循环每 60 秒唤醒一个短命令，未到期立即返回，不能随页面刷新增加网络请求。截止时间采用包含休眠的单调时钟，开机身份与截止时间原子保存；同次开机的 worker 重启、重复调用和系统时间前后跳不能重置退避。重启设备后旧单调时间失效，状态先为 stale/pending，不伪装为新成功。

每个探测为 HTTPS HEAD，不下载正文、不跟随重定向、无 curl 内部重试；连接上限 4 秒、请求上限 8 秒、父进程预算 9 秒、输出上限 1 KiB。网络请求不能使用用户 curl 配置或失控的代理环境。测量、通知和恢复日志有界。复用现有监督生命周期，不新增常驻 Rust 服务。

`.state/machines/connectivity.state` 是唯一公共规范状态，schema=1、有界 token、原子替换。producer 保存下一次到期、失败次数、恢复级别和订阅冷却；普通 reconcile 不覆盖其预算。开机身份不进入机器 JSON 或支持包。读取、health、MCP 资源及诊断导出都不发起新公网探测、不更新状态、不执行恢复。

## CON-002：差异探测与警告

Google 失败后才访问独立代理目标 `https://cp.cloudflare.com/generate_204`；两个代理目标都失败后才检查直连 `https://www.baidu.com/`。一次探测周期最多三个有界请求，正常周期只有一个。辅助成功不能代替 Google 成功；记录 primary_reason 与综合 reason，区分 DNS/TLS/连接拒绝/HTTP 错误、缺默认路由、目标特定失败和上游不可用。DNS、路由或命令缺失须如实显示 unknown/不可用，不能靠假定填成功。

WebUI 概览、诊断页和 health 显示明确 ⚠️，包括失败、重试时间和最近恢复动作。故障/恢复转换才通知，不能每次读取或每次失败重复刷通知。状态至少有 unknown、pending、online、degraded、offline、paused、stale；pending 的再次检查保留上次失败警告。恢复动作成功仅表示动作执行结果，只有后续主目标成功才能显示 online。

## CON-003：有条件自愈

至少连续两次失败、两个代理目标均失败、直连成功且没有确认缺少默认路由，才允许进入自动恢复。仅 Google 失败或整体断网继续探测和警告，不进行无依据的连续重启。恢复动作最少间隔 300 秒；依次尝试当前模式的自有路由/DNS恢复、事务性订阅刷新、当前受控核心重启。自动订阅刷新最少间隔 3600 秒，整次自动动作预算 300 秒；仍遵守既有来源下载安全、候选校验、完整批次、原子替换和失败恢复。

恢复复用生命周期/配置锁。锁忙有界返回 deferred/busy，不能重启正在被其他操作管理的核心；得到锁后重新确认模块启用、当前核心活着且归属明确。用户停止、停用、卸载或进程归属未知时暂停，不尝试启动来掩盖失败。保留 tun|ebpf、用户配置、节点选择和停止意图，不调用需要用户确认的 Android network-access 策略写入。

订阅激活或重启可能停止当前监督父循环。正在执行的恢复 worker 必须完成并发布回执；只终止有归属证据的父循环，不误杀整个进程组。恢复后的循环恰好一份，不继承配置/探测锁或一次性命令预算；中断和失败继续保留有界退避及恢复证据。

显式 service stop/restart 优先于自动恢复：停止 producer，并按完整 argv 与进程启动身份取消本模块 worker。给现有订阅 TERM/回滚流程最多15秒，持有生命周期锁直到子组结束，取消场景争锁预算最多20秒；无法完成仍明确 busy/error。取消后记录 paused/stop_requested，不自动重建监控、重放选择或启动核心；不能只杀父控制器而留下继续持锁/重启的子进程。

## CON-004：实际可用的 HTTPS 执行器

正式模块必须提供受管 `bin/curl`，不能假定 Android 系统或另一个 root 模块已提供 curl。生产 ARM64 与模拟器 x86_64 使用同一固定源码、TLS/压缩依赖及 CA 构建流程；版本、源码摘要、ABI、执行权限和 TLS 信任根随组件校验。正式下载和探测使用模块可信绝对路径，不以测试临时注入的工具代替生产依赖证据。

禁用用户 curl 配置，清理可改变代理、CA、TLS 后端和 TLS 密钥日志行为的继承环境；显式代理与证书验证继续生效。工具缺失、不可执行或输出无效时保留 `probe_unavailable`/`probe_invalid`，不能将本机执行器故障归为上游网络失败，更不能满足自动恢复的网络证据条件。

实际 Android 验收应在无系统 curl 的环境中执行安装后的模块 curl，核对版本、HTTPS/TLS/gzip能力及嵌入CA的实际内容摘要，完成证书正确/错误对照。至多一次显式产品 tick 验证实际请求或既有有效探测结果；保持去重、到期时间和原预算，不能改状态强迫重复请求。Google 204、网络失败和未执行分别记录；导出本身仍不联网。

## CON-005：TUN 自动路由恢复

复用同一 watchdog，每 60 秒独立观测当前 TUN 的必要 RPDB/FIB 证据，不受 Google 探测退避影响。只有显式 tun、auto_route=true、核心归属明确且实际启动满 90 秒，同一核心启动身份的连续两次完整观测均确认必要资源缺失，才允许恢复；任一观测未知、事务未完成、模块停用或用户停止均不能触发。present/unknown 或核心换代清除连续缺失计数，不能清除同次开机的恢复预算；已有预算损坏保持不可恢复，不按零次重新授权。

取得现有配置/生命周期锁后重新核对上述条件，调用当前核心的标准重启流程，由原所有者重建规则；不猜固定优先级、不直接重放或清空系统路由。所有联网恢复动作共享至少 300 秒冷却，TUN 重启依次退避 300/600/1200 秒，同次开机最多尝试 3 次；先原子预留次数再执行，CLI/worker 重跑与恢复成功不重置预算。耗尽后继续观察和告警，只有新开机重置。

在同一 connectivity.state 内持久化有界 tun_* 字段，通过只读 `tun_auto_route` 对象单独公开状态、时间、连续缺失数、尝试数和动作结果。顶层 Google/mixed_proxy 字段保持原义，重启动作成功不等于路由或应用流量恢复。普通读取、health 和导出均不执行恢复；公共数据不包含 PID、boot 身份或原始规则。

| CON-A03 | 并发 tick/status、生命周期锁忙、恢复动作/订阅冷却 | 单 producer、有限争锁；无重复探测/动作；300/3600 秒分别生效 |

| CON-A05 | 修复、订阅失败回滚、重启；监督父循环在刷新中被停止 | 回执完整，只有一个恢复循环，无锁 FD/短预算继承，用户选择保留 |
| CON-A06 | 真实发行核心与 CLI，固定合成配置，TUN/eBPF/应用流量 | 分别记录配置 check、受控进程模拟、回环请求、公网请求和真机结果；权限阻断保留原错误，不能把模拟数字当真实吞吐 |
| CON-A07 | 无系统curl的真实Android；正式组件安装/复用、TLS正确/错误证书、嵌入CA、一次到期或已执行的产品探测 | 受管curl及信任根真实可执行；经过当前mixed入口保留TLS与204判定；有界请求/缓存结果有实际证据，非probe_unavailable；私密订阅无须注入，外网失败不伪装成功；缺执行器单独报告且不盲目恢复 |
| CON-A08 | TUN 缺失/恢复/未知、启动宽限、busy、stop、事务、ebpf、auto_route=false、时钟及 worker 重跑 | 独立观测不改变 Google 结论；双确认、共享冷却和同 boot 3 次预算准确；未知和停止零恢复，锁内重新确认 |
| CON-A09 | 固定生产 CLI/core 的 Android/KernelSU 模拟器，真实应用 UID 非 DNS UDP，精确删除自有 RPDB 规则及受控上联 down/up | 注入前成功；故障时核心启动身份、TUN、FIB 保留而 readiness=false、应用失败；正常 tick 恢复规则和同应用新 UDP 请求；三次探针均证明接收端绑定/关闭和实际请求，绑定或清理失败不算断流；注入期间外部规则不变，跨恢复的系统网络编号变化须核对独立 netd 元数据、接口/权限/FIB，并精确派生全局和逐应用 selectors，仅替换 netId，其余规则及重复次数相同；保留 TCP 正反控制，原配置/测试资源恢复，缺少或跳过任一步不能通过 |

CON-A09 的 schema=1 证据保留前后 netd 网络清单、完整 metadata、eth0 接口索引/FIB 与 RPDB 规则。只在同一 PHYSICAL 网络的权限为已知 NONE、NETWORK 或 SYSTEM 且前后一致，接口/索引/FIB、Allowed UID ranges、Per-app UID ranges 及其他网络均不变时，接受该网络的 netId 变化。采集器与独立报告门禁分别从这些已核验字段派生选择器。

全局规则按该网络的实际权限核对 mark/mask；所有这些规则均要求 `from all`、`iif lo` 和 `lookup eth0`：

| Required permission | 优先级 16000 的 mark/mask | 优先级 23000 的 mark/mask |
| --- | --- | --- |
| NONE | `(0x10000 \| netId) / 0x1ffff` | `netId / 0x1ffff` |
| NETWORK | `(0x50000 \| netId) / 0x5ffff` | 必须不存在 |
| SYSTEM | `(0xd0000 \| netId) / 0xdffff` | 必须不存在 |

逐应用规则不随上述权限改变：每个元数据范围须有 `15000+prio`、`22000+prio` 两条，mark 分别为 `0x10000 | netId`、`netId`，mask 均为 `0x1ffff`，并匹配精确 `uidrange`、`iif lo`、`lookup eth0`。逐项核对完整字段和重复次数；重复或重叠的元数据范围保留各自规则。无法完整解析、缺项、多项、权限变化或无关规则变化均失败。该扩展沿用证据 schema 与生产机器接口。
