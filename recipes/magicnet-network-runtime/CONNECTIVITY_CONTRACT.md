# 低频联网探测与恢复

本合同定义连接后的主动探测。进程存活、配置有效、本机 API 可用与外网请求成功分别是不同证据。主目标为 `https://www.google.com/generate_204`，必须经当前受控 sing-box 的本机 mixed 入口；TLS 校验通过且 HTTP 204 才记为 Google 在线。该结果证明此代理路径，不能代替某个 Android 应用 UID、热点客户端或全部 TUN/eBPF 数据面的实际流量验收。

## CON-001：频率、预算与状态

正常每 300 秒探测一次。连续失败采用 60、120、240、480、960、1800 秒的指数退避，此后上限保持 1800 秒；成功后恢复 300 秒。已有监督循环每 60 秒唤醒一个短命令，未到期立即返回，不能随页面刷新增加网络请求。截止时间采用包含休眠的单调时钟，开机身份与截止时间原子保存；同次开机的 worker 重启、重复调用和系统时间前后跳不能重置退避。重启设备后旧单调时间失效，状态先为 stale/pending，不伪装为新成功。

每个探测为 HTTPS HEAD，不下载正文、不跟随重定向、无 curl 内部重试；连接上限 4 秒、请求上限 8 秒、父进程预算 9 秒、输出上限 1 KiB。网络请求不能使用用户 curl 配置或失控的代理环境。测量、通知和恢复日志有界。复用现有监督生命周期，不新增常驻 Rust 服务。

`.state/machines/connectivity.state` 是唯一公共规范状态，schema=1、有界 token、原子替换。producer 保存下一次到期、失败次数、恢复级别和订阅冷却；普通 reconcile 不覆盖其预算。开机身份不进入机器 JSON 或支持包。读取、health、MCP 资源及诊断导出都不发起新公网探测、不更新状态、不执行恢复。

## CON-002：差异探测与警告

Google 失败后才访问独立代理目标 `https://cp.cloudflare.com/generate_204`；两个代理目标都失败后才检查直连 `https://www.baidu.com/`。一次探测周期最多三个有界请求，正常周期只有一个。辅助成功不能代替 Google 成功；记录 primary_reason 与综合 reason，区分 DNS/TLS/连接拒绝/HTTP 错误、缺默认路由、目标特定失败和上游不可用。DNS、路由或命令缺失须如实显示 unknown/不可用，不能靠假定填成功。

WebUI 概览、诊断页和 health 显示明确 ⚠️，包括失败、重试时间和最近恢复动作。故障/恢复转换才通知，不能每次读取或每次失败重复刷通知。状态至少有 unknown、pending、online、degraded、offline、paused、stale；pending 的再次检查保留上次失败警告。恢复动作成功仅表示动作执行结果，只有后续主目标成功才能显示 online。

## CON-003：有条件自愈

至少连续两次失败、两个代理目标均失败、直连成功且没有确认缺少默认路由，才允许进入自动恢复。仅 Google 失败或整体断网继续探测和警告，不进行无依据的连续重启。恢复动作最少间隔 300 秒；依次尝试当前模式的自有路由/DNS恢复、事务性订阅刷新、当前受控核心重启。自动订阅刷新最少间隔 3600 秒，整次自动动作预算 300 秒；仍遵守既有来源下载安全、候选校验、完整批次、原子替换和失败恢复。

恢复复用生命周期/配置锁。锁忙有界返回 deferred/busy，不能重启正在被其他操作管理的核心；得到锁后重新确认模块启用、当前核心活着且归属明确。用户停止、停用、卸载或进程归属未知时暂停，不尝试启动来掩盖失败。保留 tun|ebpf、用户配置、节点选择和停止意图，不调用需要用户确认的 Android network-access 策略写入。

订阅激活或重启可能停止当前监督父循环。正在执行的恢复 worker 必须完成并发布回执；只终止有归属证据的父循环，不误杀整个进程组。恢复后的循环恰好一份，不继承配置/探测锁或一次性命令预算；中断和失败继续保留有界退避及恢复证据。

显式 service stop/restart 优先于自动恢复：停止 producer，并按完整 argv 与进程启动身份取消本模块 worker。给现有订阅 TERM/回滚流程最多15秒，持有生命周期锁直到子组结束，取消场景争锁预算最多20秒；无法完成仍明确 busy/error。取消后记录 paused/stop_requested，不自动重建监控、重放选择或启动核心；不能只杀父控制器而留下继续持锁/重启的子进程。

## 验收 CON-A01–A06

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| CON-A01 | 正常、连续故障 2 小时、成功恢复；时钟前跳/后跳、worker 重启 | 正常 300 秒；失败序列及 1800 秒上限准确；预算保留，状态读取不发请求 |
| CON-A02 | 只主目标失败、双代理失败直连成功、全部失败、DNS/TLS/缺路由 | 辅助按条件执行，每周期最多三次；主目标失败保持警告，原因不混为“已联网” |
