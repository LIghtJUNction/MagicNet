# 命令预算、服务交接与 PID 校验

启动命令只负责把服务带到就绪状态；就绪后，服务的存活由模块生命周期管理。一次命令的超时和进程组不能继续决定长期服务的寿命。

## LIFE-001：预算只属于当前操作

监督器启动的短预算与后续热点重协调、配置应用的预算分别计算。当前控制命令消费 `MAGICNET_COMMAND_TIMEOUT` 后，在启动运行时 worker 的边界移除该一次性覆盖，避免 worker 派生的长期守护把它带入后续命令。调用方仍遵守原预算、超时清理与父进程死亡保护；不能仅把默认数值调大。

参考实现的普通命令默认预算为 180 秒；监督器启动默认 45 秒、最高 60 秒。这些数值分别限制对应操作，不是启动性能承诺，也不能作为守护内部后续请求的隐式配置。

## LIFE-002：就绪前由启动方负责回收

新核心启动时建立独立的 session/进程组，并由临时启动 worker 直接持有子进程句柄。控制进程或外层 launcher 在交接确认前死亡、交接通道关闭、就绪验证失败或期限到达时，worker 回收本次核心及其受控子进程；先 TERM，必要时 KILL，最后回收退出状态。发完最后一个组信号前不能提前 reap 核心主进程，以免其 PID/PGID 被复用。仅 `nohup` 不能隔离进程组，单独 `setsid` 也不能提供就绪前的失败清理。

交接通道和句柄不得被核心或无关孙进程继承，以免父进程退出后仍被错误保持。内部启动入口只接受固定核心和经过验证的模块路径、配置与工作目录，不提供任意程序执行接口。机器模式仍先由 schema-1 dispatcher 接管。

就绪前的启动和失败清理必须持续保护已有配置锁。启动前先持有原 metadata guard，再将同一锁句柄传给临时 worker；原控制进程或外层 launcher 死亡不能让另一个 writer 在旧核心仍清理时回收锁并开始下一次写操作。控制调用有界返回；若内核阻塞导致 KILL 后仍无法确认退出，worker 继续保锁等待，结果为清理尚未完成，不伪报已回收。复用原有锁，不建立第二套公共状态。

这里的故障覆盖是控制进程和外层 launcher 的退出。直接负责回收的私有 worker 自身被外部单独 SIGKILL，或系统级故障使其无法执行，仍是未覆盖的故障边界；不能把对控制方死亡的处理写成对任何进程死亡都能兜底。

## LIFE-003：就绪后移交给模块生命周期

只有模块完成本次核心的 PID 身份和既有 readiness 检查，才发送交接确认。私有 worker 接受确认并再次核实核心仍在运行后解除启动保护并退出，保留核心自身的独立 session；不得增加永久守护进程或轮询线程。旧控制命令随后超时或被杀，不能向已交接核心发送同组 TERM/KILL。

正常调用必须等待私有 worker 成功退出后才能报告启动成功。外层 launcher 写入确认不等于它已观察到交接结果；若它在确认被接受的边界死亡，核心可能已经完成交接，后续以模块 reconcile 的实际进程与 readiness 证据确定状态。

交接成功不表示整次配置事务必然提交。后续路由、策略或状态发布失败仍按原事务回滚，通过身份校验的模块停止路径处理已交接核心；不能因为核心脱离控制进程组而跳过回滚。

## LIFE-004：先验证十进制 PID，再读取或发信号

所有锁 owner 与信号入口统一接受规范十进制 `1..2147483647`，拒绝空值、零、前导零、符号、表达式、非数字、过长和越界字符串。范围验证的每一个算术操作数都必须能被有符号 32 位整数表示；不能先让十位输入溢出，再拿溢出结果比较上界。

允许使用长度和安全十进制片段比较，避免为每次 PID 校验额外启动 awk/sed。数值通过后仍必须检查 `/proc` 的启动身份与模块归属。确认死亡可回收锁；身份无法读取或存在矛盾时保留 unknown，不向其他进程发信号。配置锁、订阅更新锁、核心停止和订阅信号路径使用同一校验实现。

## LIFE-005：配置锁属于实际执行者

锁 owner 使用实际执行临界区的 shell PID 和 `/proc` 启动身份。POSIX 子 shell 中的 `$$` 可继续表示父 shell，因此不能直接作为执行者身份。获取成功才保存 owner token；释放必须匹配 token 和当前实际进程，子进程不能释放父进程的锁。启动时间短暂不可读时可以复用已验证的当前持锁 token，身份冲突或 unknown 仍不能删除他人的锁。旧 PID/start 标记继续按原校验导入。

| 编号 | 输入与故障 | 预期 |
| --- | --- | --- |
| LIFE-A08 | Bash、mksh、BusyBox、POSIX sh 的嵌套/后台执行者获取锁后退出或被终止，父 shell 保持存活 | marker 绑定实际执行者；确认退出后下一写者能回收，不持续等待父 shell |
| LIFE-A09 | 活/暂停/身份不可读 owner、正常嵌套、子进程尝试释放父锁、获取失败、释放阶段启动时间暂时不可读 | 保持单写者和 caller signal handler；只释放自己已取得的锁；清理失败如实报错 |

停止继续先撤销自有路由和 DNS 捕获，清理失败保留核心；此修复不提供强删锁或跳过清理入口。

LIFE-A10：并发两个启动入口先观察 stopped，再同时请求 start，只发布一个 watcher；重复 start 保持 PID，stop 与发布串行。watcher 存活时生命周期锁已释放；只关闭该锁描述符，不关闭无关继承 fd。flock 能力探测必须区分正常 contention 与不支持选项。

## LIFE-006：模块控制锁与框架锁分别保护自己的临界区

模块的 status/start 重查和 stop 序列化，与框架内部的 watcher 发布/回收，不能由父子调用通过独立文件句柄重复锁定同一 inode。父进程持锁等待子进程、子进程等待同一锁，会形成自等待；关闭子进程继承的 fd 不会释放父进程仍持有的锁。

保留模块控制层与框架层的各自互斥，使用不同的私有锁文件并保持固定获取顺序。模块锁的竞争必须有界返回，框架的既有 ownership 校验继续生效；不通过延长命令期限、移除互斥或跳过监督器掩盖问题。长期 watcher 不继承控制层锁。

LIFE-A11：用固定版本的真实 kamfw/fswatch.sh 验证首次启动、重复启动、并发启动、停止和忙锁期限。必须包含旧的同路径双层锁会阻塞的对照，以及修复后 watcher 唯一、健康 PID 保持、锁释放和无相关 fd 继承；仅以不加锁的 fswatch 替身通过不能替代此项集成证据。

fswatch 的生成文件排除同时支持字面 basename 与带目录的相对路径；例如 `sing-box/config.json` 不排除其他父目录的同名文件。批量扫描优化不得让 materializer 自己的输出重新进入快照，形成配置应用反馈循环；也不能扩大排除范围而漏掉真正的用户输入。以真实快照验证生成文件不触发变化、同名不同父目录和实际用户文件仍可触发。

## LIFE-007：订阅激活恢复完整的维护集合

订阅重启须在配置锁内锁存完整维护恢复意图与原 fswatch 活动状态，在初始 journal 恢复、激活、失败回滚及信号路径释放配置锁后，复用正常配置启动链恢复维护集合。订阅更新 wrapper 的 update owner 保持到恢复结束；fswatch=off 仅抑制 fswatch。已停止核心不启动 worker；核心身份不明保持 unknown。正常更新收尾的维护恢复失败记录 supervisor_restore_failed；初始恢复失败和信号中断保留各自原因。公共状态仍仅暴露是否存在原因，不增加原始错误文本。

独立 common 启动恢复使用自己的配置锁与监督恢复作用域，不获取订阅 update owner。若继承已持配置锁或已有延迟恢复上下文，返回 2 并保留 journal、活动配置和调用方 pending，不释放调用方锁或抢先恢复。仅当原恢复成功时才用随后维护恢复的失败替换返回码。

orphan 发现先按目标监督器的真实 loop/worker 命令筛选，再以现有 /proc 存活状态及精确 argv 核验。无关模块 CLI/core 的不可读 cmdline 不污染该监督器；真实候选身份不明或 ps 失败继续返回未知，不扩大可发信号的 argv 集合。

正常 service stop 的清理门槛保持。订阅重启在确认旧核心停止后，分别处理 worker 停止、热点路由及 DNS 清理；仅热点路由清理独立失败可以保留 owned journal、给出警告，并由既有 post-start/接口 watcher 重试。此时核心 ready 不能代表热点 ready。worker 停止、身份核验和 DNS 清理失败仍阻断新核心，且独立 DNS 清理均应尝试；旧核心归属或终止未知时不改变其策略与监督状态。

LIFE-A12：覆盖无关 CLI/core/其他 loop 的不可读身份、真实候选不可读、ps 部分输出后失败，以及热点清理 1/2、worker 停止 1/2 和 DNS 清理失败。无关目标不误阻断；真实未知不授权；只有热点独立失败允许继续已有重协调路径。保留 TERM/KILL、readiness 和一般 stop 的反例。
